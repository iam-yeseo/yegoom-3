# 예굼방 아케이드 3

첨부된 게임 화면 HTML의 디자인을 React로 옮긴 예굼방의 새 시작입니다. Cloudflare Workers가 화면과 API를 제공하고 D1에 계정·세션·게임 기록을 저장합니다. Cloudflare 계정을 연결하지 않아도 로컬에서 실행할 수 있습니다.

## 현재 동작

- 골드·이용권은 append-only 원장 INSERT와 같은 트랜잭션에서 갱신하는 잔액 캐시로 조회·구매 조건을 검사합니다. 주간 점수는 해당 주차만 합산합니다.
- bootstrap은 보이는 홈·랭킹에서 30초, 나머지 화면에서 60초 간격으로 조회합니다. 숨긴 탭·뽑기 화면·미리보기에서는 폴링하지 않고, 최근 10초 안에 조회했다면 탭 복귀 시 중복 요청을 생략합니다.
- 운영·주식·뽑기 화면과 뽑기 물리 코드는 진입할 때 불러옵니다. PWA의 오프라인 미리보기용 정적 파일 사전 캐시는 유지합니다.
- 매일 KST 00:00에 만료 세션·로그인 시도와 생성 후 30일 넘고 판이 종료된 일부 캐치마인드 요청 영수증을 최대 500개씩 정리합니다. 원장·그림·답변·현재 판·답변이 참조하는 영수증은 보존합니다. [무료 플랜 측정과 한계](docs/free-plan-budget.md)
- 홈 상단은 프로필 사진(없으면 선택 캐릭터)과 `닉네임님`, 점수 제목은 `이번 주 점수`로 표시합니다. 긴 닉네임은 말줄임하며 아침·저녁 테마와 미리보기에 함께 적용합니다.
- 주간 순위는 동점을 같은 순위로 계산합니다(`1·1·3위`). 홈은 공동 1등·공동 2등·선두와의 점수 차이를 구분하고, 모두 0점이면 점수 안내만 표시합니다.
- 닉네임은 문장·사진 설명·알림에서 `이름님`으로 표시합니다. 홈 주간 랭킹과 랭킹 화면의 이름표·사진 설명은 `이름`만 표시하며, 닉네임 입력값과 로그인 아이디는 원본을 유지합니다.
- 날짜·시각은 KST 기준 `2026년 11월 04일`, `17시 30분`, 기상·퇴근 예측/정답은 `09시 12분 36초` 표시. 입력/API 값과 남은 시간 카운트다운은 기존 형식 유지
- 하단 시트·모달은 공통 열기/닫기와 페이지 스크롤 잠금을 사용하며, 등장 중 임시 스크롤바와 화면 너비 이동을 방지
- 아이디·비밀번호 로그인, 서버 세션, 로그아웃, 운영자/플레이어 구분
- 내 정보의 비밀번호 변경: 현재 비밀번호 확인, 새 비밀번호 12~128자·확인 입력, 보기/숨기기. 플레이어·운영자 모두 자기 비밀번호를 바꾸며 현재 기기 세션만 교체해 유지하고 다른 기기는 다시 로그인합니다. 미리보기에서는 비활성화합니다.
- 닉네임 수정과 프로필 사진 자르기·저장·삭제: 원형 아바타에 사진을 표시하고 큰 캐릭터는 유지
- 기상시간·퇴근시간은 `HH:MM:SS`, 행운 점수는 0~100 정수로 예측 저장/수정
- 행운 점수는 증거 사진을 올려야 정답 저장 가능: 공개 전에는 출제자만 보고 공개 후 오늘 결과·최근 기록에서 확대 보기
- 출제자 전용 화면: 기상은 확인 후 서버 시각으로 즉시 공개, 퇴근은 입력 시각에 자동 공개, 행운 점수는 힌트와 함께 18:00 자동 공개(퇴근·행운은 조기 공개 가능)
- 첫 예측 저장 시 참여 골드, 공개 후 정확도 점수와 공동 1등 골드를 판에 저장된 규칙으로 멱등 지급(기본 참여·1등 각 100G)
- 게임별 최근 공개 3판 기록(오늘 제외), 공통 규칙으로 생성한 게임 방법·점수표, 주간 점수 순위(주간 보상 없음)
- 서버 KST 기준 하루 한 번 출석: 연속 7·14일째마다 500G, 그 밖에는 100G 지급, 서버 월간 기록과 7일 주기 표시
- 2026-11-03(KST) 출석부터 골드와 함께 데일리 로또·스피또 이용권 각 1장 지급. 이전 기록·지급과 11-02 런칭 선물은 유지
- 출석 완료 후 홈 카드는 연출이 끝나면 한 줄로 접히며 다시 펼칠 수 있음
- 캐릭터 선택 서버 저장: 다른 기기의 홈·랭킹·결과·아바타에도 반영, 기존 기기 선택은 서버 값이 없을 때 한 번 이관
- 예굼쿠지: 서버 공용 100장 판, 6번째부터 누진 가격, 등급별 골드·점수·이용권과 라스트원 지급
- 데일리 로또: 1~25 중 5개 선택, 매일 KST 17시 30분 판매 마감·추첨, 이후 구매는 다음 날 대상, 표별 당첨금 멱등 정산
- 최근 10분의 로또 1~3등·스피또 당첨 소식을 다른 사용자에게 4초 배너로 표시
- 스피또: 구매 순간 서버에서 10% 당첨 여부·캐릭터 배치·1,500G 지급 확정, 나중에 다시 긁어도 결과 유지
- 홈 출석 카드 아래에서 오늘 추첨 회차의 완료를 안내합니다. 장수만 표시하고 결과 금액은 로또 화면에서 확인하며, 화면 진입이나 ×로 해당 계정·회차 안내를 숨깁니다.
- 로또·스피또 결제는 골드/이용권 두 칸이며 최근 7일 기록을 구매일별로 묶어 표마다 한 줄로 표시합니다. 스피또 그룹 합계는 같은 화면에서 긁어 공개한 표만 더하며 두 게임 모두 합계가 0이면 금액을 숨깁니다. 표시 기간 밖의 미정산 표도 지급은 유지합니다.
- 스피또 덮개는 실제 표시 크기와 DPR(최대 2)에 맞추고 폰트를 기다려 글자를 그립니다. 기록에서 표를 다시 고를 수 있으며 `한 번에 긁기`도 지원합니다.
- 슬롯머신: 골드로만 1회 500G, 서버에서 7% 확률로 7·7·7과 2,000G 즉시 지급. 일일 제한은 없으며 낙첨은 같은 그림 세 개가 나오지 않습니다. 최근 7일 중 최대 20회 기록과 응답 유실 시 같은 요청으로 결과 확인을 제공합니다.
- 골드 또는 이용권 결제, 보유 이용권 표시, 구매 요청 재시도·동시 요청의 중복 차감 방지
- 캐치마인드: 5번째 오답에 힌트, 10번째 오답에 보상 없이 즉시 종료. 첫 정답자는 3점·5G를 받고, 다음 출제는 정답 여부와 관계없이 활성 플레이어의 username 순서로 순환합니다.
- 캐치마인드 다음 출제자가 판 종료 후 10분 동안 시작하지 않으면 다른 플레이어가 차례를 넘길 수 있습니다. 비활성 차례와 중단된 초안은 다음 활성 플레이어가 이어갑니다.
- 출제자에게 보여 준 제시어(바꾸기 전 단어 포함)는 400개를 모두 쓰기 전까지 다시 나오지 않습니다. 소진 후 새 묶음을 시작하고, 남은 단어 30개 이하는 운영 탭에 안내합니다.
- 캐치마인드는 버전이 같으면 상태를 재사용합니다. 공개 판은 5초, 대기·타인의 초안·종료는 10초, 내 초안·숨긴 화면은 주기 조회를 중단합니다. 계정이 바뀌면 이전 비공개 제시어를 지웁니다.
- 캐치마인드 지난 판 카드와 `#/play/catchmind/gallery`: 종료된 판만 최신순 3×3, 9개씩 더 보기, 공용 확대 모달의 이전·다음 판과 키보드 탐색. 미리보기도 서버 없이 동작
- 펜·지우개·영역 채우기·실행 취소, HSV·투명도·HEX·견본·최근 색을 지원하는 컬러 피커. 진행 중 획은 오버레이에 프레임당 한 번 그리고, 되돌리기는 최대 10개 비트맵으로 보관합니다.
- 전역 터치 이펙트: 누른 위치에 2px 코랄 테두리 링과 6px 색 점이 잠깐 나타나며, 입력·그리기 영역과 reduced motion에서는 생략
- 한국 시간 기준 마감, 공개 전 정답 보호, 날짜가 바뀐 화면의 제출 차단
- Claude Design 시안대로 만든 홈(아침/저녁), 하단 탭, 주간 랭킹, 출석 체크, 내 정보(캐릭터 선택·골드/점수 내역)
- 랭킹 화면의 일간·주간·월간 토글(선택 기억): 시상대와 전체 순위에 프로필 사진(없으면 선택 캐릭터)과 닉네임, 기간별 내 점수 막대(게임별·요일별·주차별), 모든 플레이어의 점수 획득 기록(누가·언제·무슨 게임·몇 점, 20개씩 더 보기). 점수는 게임 날짜 기준으로 묶고 `GET /api/ranking?period=day|week|month`가 세션 확인 외 2쿼리로 읽습니다. 미리보기도 서버 없이 같은 집계를 씁니다.
- 캐릭터 뽑기: 개인별 물리 기계, 10초 조작·하강 멈춤·서버 결과 재생, 무료/구매 코인, 인형·클리어 보상
- 뽑기 기계·지갑·안내는 앱 본문 폭을 사용하며, 낮은 화면에서는 조작 버튼이 보이도록 캔버스의 600:420 비율을 유지해 줄입니다.
- 뽑기는 정지 상태의 반복 렌더·그리기를 멈추고 배경·인형 그림자를 재사용합니다(DPR 최대 2). 서버 결과의 재생 계산은 미리 준비한 브라우저 Web Worker에서 같은 물리 엔진으로 실행하며, 미리보기와 운영자 기계에도 적용합니다.
- 주식 시장 진입 시 “준비 중” 안내: 홈·게임 탭·직접 주소·미리보기에서 동일하게 적용
- 2026-11-02(KST) 출석한 활성 플레이어에게 런칭 선물(로또·스피또 이용권 각 5장)을 한 번 지급
- 운영자 전용 운영 탭: 예측 배점·골드·마감·ON/OFF의 날짜별 설정과 최근 변경 20건
- 운영자 전용 인형뽑기: 코인 없이 무제한 플레이·강집게 테스트, 보상 없음, 다음 플레이부터 집게 힘 설정 적용
- 로그인 전 미리보기(`#/preview`), 서버 없이 동작하는 운영 미리보기(`#/preview/admin`)
- 설치 가능한 PWA, 로컬 폰트와 정적 화면의 오프라인 재방문

주식은 아직 서버 기능이 없는 **화면 단계**입니다. `shared/balance.ts`의 `FEATURES.stock = false`로 진입을 막고 있으며, `true`로 바꾸면 보존한 목록·상세·장 마감·상장폐지 화면을 다시 사용할 수 있습니다. 예측 게임의 기본값과 출석·상점·캐치마인드·캐릭터 뽑기의 공개 규칙은 `shared/balance.ts`에 있습니다. 실제 예측 게임은 서버가 제공하는 판별 `rules`를 Worker와 화면에서 함께 사용합니다. 도움말의 시간 차이는 점수표 값에서 계산한 시·분·초 단위로 표시합니다. 나머지 화면의 잠정값과 미리보기 데이터는 `src/sample.ts`에 남아 있습니다. 홈의 골드·주간 점수와 내 정보 내역은 실제 원장 합계·기록을 표시합니다. 기존 기기 출석 기록은 서버로 옮기지 않고 정리하며, 미리보기의 출석·캐릭터 선택은 기기 안에서만 동작합니다. 미리보기의 상점·캐치마인드·캐릭터 뽑기도 서버 없이 동작하며 실제 계정에 반영되지 않습니다. 후속 개발 범위는 [2차 계획](docs/plan-v2.md)을 따릅니다.

## 로컬 시작

Node.js 22.12 이상을 권장합니다.

```sh
npm ci
npm run build
npm run db:migrate
npm run user:create -- --username min --display-name min
npm run user:create -- --username siwon --display-name siwon
npm run user:create -- --username yeseo --display-name yeseo
npm run user:create -- --username admin --display-name 운영자 --role admin
npm run dev
```

각 계정의 비밀번호를 터미널에서 입력합니다(12–128자, 화면에 표시되지 않음). 기본 비밀번호는 없습니다. `http://localhost:5173`에서 사용합니다. 계정 생성 없이 로그인 화면의 **먼저 체험해 보기**로 디자인을 확인할 수도 있습니다.

`npm run dev`는 Vite와 로컬 Worker를 함께 실행합니다. 처음에는 정적 파일을 빌드한 뒤 시작합니다. 프런트엔드 변경은 Vite가 바로 반영하고 Worker 변경은 Wrangler가 반영합니다. 로컬 D1은 `.wrangler/state`에 보존되며 Git에서 제외됩니다.

빌드 결과와 서비스 워커를 확인하려면:

```sh
npm run build
npm run preview
# http://localhost:8787
```

서비스 워커는 빌드 결과에서만 등록됩니다. 개발 서버에서는 등록하지 않습니다. PWA 설치에는 HTTPS 또는 localhost가 필요합니다. iOS에서는 Safari의 공유 → 홈 화면에 추가를 사용합니다. 로그인·상태 조회·게임 저장은 오프라인에서 이용할 수 없으며, 제출을 나중에 자동 전송하지 않습니다. 오프라인에서는 저장된 화면과 미리보기를 이용할 수 있습니다. 서비스 워커는 캐치마인드 이미지를 포함한 모든 `/api` 경로를 캐시하지 않습니다.

## 계정 관리

같은 사용자명으로 `user:create`를 실행하면 비밀번호와 표시 이름을 갱신하고 기존 세션을 모두 해제합니다. 새 사용자명으로 실행하면 플레이어를 추가합니다. 운영자 비밀번호를 초기화할 때도 `--role admin`을 반드시 함께 지정합니다. 기존 기록을 보존하면서 계정을 중지하려면:

```sh

```

운영자 계정은 예측·출제·출석·런칭 선물 수령·상점 구매·캐치마인드·코인 구매에 참여하지 않습니다. 인형뽑기는 운영자 전용 기계에서 코인 없이 테스트하며 골드·점수·당첨 소식이 생기지 않습니다. 게임 설정은 하단 운영 탭에서, 계정 생성·중지는 기존 CLI에서 관리합니다. 초기 예측 출제자는 `min`, `siwon`, `yeseo`로 지정되어 있습니다. 원격 DB 계정을 만들거나 중지하려면 별도로 `--remote`를 지정해야 합니다. 비밀번호를 CLI 인수나 저장소에 기록하지 마세요. 자동화에서는 `YEGOOM_PASSWORD` 환경변수를 사용할 수 있습니다.

## Cloudflare 연결 후 배포

원격 D1은 `yegoom-db`(`088d5d45-6dea-43c1-b9b2-a972aa5a01d0`)이며 `wrangler.jsonc`에 연결되어 있습니다. 기존 yegoom의 DB와 기록은 연결하지 않습니다. Cloudflare 대시보드의 Git 연결 빌드는 main에 푸시될 때 이 설정으로 배포합니다. 다른 DB로 바꿀 때는 `database_name`과 `database_id`를 함께 바꿉니다. 존재하지 않는 ID면 배포가 `D1 binding 'DB' references database … which was not found [code: 10181]` 오류로 실패합니다.

배포는 테이블을 만들지 않습니다. 처음 한 번, 그리고 `migrations/`가 바뀔 때마다 원격 마이그레이션을 실행하고 계정을 만듭니다.

```sh
npx wrangler login
npm run db:migrate:remote
npm run user:create -- --username min --display-name min --remote
npm run user:create -- --username siwon --display-name siwon --remote
npm run user:create -- --username yeseo --display-name yeseo --remote
npm run user:create -- --username admin --display-name 운영자 --role admin --remote
npm run deploy:check
npm run deploy
```

Phase 6은 **`0006_claw.sql` 마이그레이션이 필요합니다**. 기존 `0001`~`0005`는 수정하지 않았습니다. 운영 반영 순서는 **PR 리뷰 → 운영자가 머지 전에 `npm run db:migrate:remote` 실행 → PR 머지 → main 배포**입니다. 새 테이블만 추가하므로 기존 배포와 호환됩니다. 이번 개발 작업에서는 원격 DB 변경·머지·배포를 실행하지 않습니다.

개선 PR 2는 **`0010_balances.sql`과 `0011_query_maintenance.sql`이 필요합니다**. 원격 마이그레이션 → 머지 → 배포 순서이며, 이 작업에서는 세 단계 모두 실행하지 않습니다. 기존 코드의 원장 쓰기와 호환되는 추가 테이블·트리거·인덱스입니다. 초기 잔액 backfill은 한 번 실행되므로 운영자는 남은 D1 일일 읽기·쓰기 예산을 확인합니다.

Workers Static Assets와 D1 이외의 서비스는 초기 실행에 필요하지 않습니다. 자동 정답 공개는 서버가 요청 시 공개 시각을 판단합니다. Cron은 하루 한 번 기록 정리만 하며, bootstrap·게임·기록 조회는 공개됐지만 정산되지 않은 판을 정산하고 지급 고유 reference로 중복을 막습니다. 점수의 주차는 정산 시각이 아닌 게임 날짜의 KST 월요일입니다. 정답 없는 판은 정산하지 않으며 이미 받은 참여 보상은 유지됩니다. 홈·랭킹은 30초, 다른 화면은 60초마다 보일 때만 갱신하고 뽑기에서는 중지합니다. 다시 활성화될 때 마지막 성공 조회가 10초 이상 지났으면 갱신합니다.

데일리 로또는 bootstrap과 상점 요청에서 추첨 시간이 지난 표를 정산하므로 며칠 뒤 접속해도 누락된 당첨금을 받습니다. 이용권 캐시는 append-only 원장의 합계와 일치하며 구매는 잔액 검사·원장과 캐시 차감·결과 저장을 같은 D1 batch로 처리합니다. 구매 응답을 받지 못하면 같은 요청 번호로 결과를 재확인하며, 이미 처리한 구매를 다시 차감하지 않습니다.

캐치마인드는 날짜와 무관하게 한 판씩 이어집니다. 제시어는 출제자만 보고, 끝난 판은 결과를 유지하다가 다음 출제자가 새 판을 시작합니다. 답변·종료·차례 이동·보상·버전·제시어 예약은 같은 D1 batch에서 처리하며 재요청은 오답 횟수나 지급을 늘리지 않습니다. 점수 주차와 일별 그래프는 그림을 공개한 KST 날짜를 사용합니다. 공개한 그림은 바꿀 수 없으며 정사각형 PNG/WebP의 디코딩된 이미지 바이트가 300KiB 이하여야 합니다. `since` 버전이 같은 조회는 인증 포함 2쿼리이며, 초기/변경된 응답에만 전체 상태를 담습니다. 상태별 간격과 숨김 중단은 미리보기에도 같습니다.

개선 PR 4는 **`0012_catchmind_used_words.sql` 마이그레이션이 필요합니다**. 운영자의 원격 마이그레이션 → 머지 → 배포 순서입니다. 진행 중인 판의 그림·오답 수·기록은 보존하고 새 배포부터 5/10 기준을 적용합니다. 이미 끝난 현재 판은 실제 출제자의 다음 활성 플레이어로 넘깁니다. 기존 탭은 배포 후 새로고침해 새 규칙 안내를 받습니다. 이번 작업에서 원격 변경·머지·배포는 실행하지 않습니다.

캐치마인드 상태 응답은 그림 본문 대신 판 ID별 이미지 주소를 제공합니다. 그림은 `GET /api/catchmind/rounds/:id/image`에서 PNG/WebP로 받고, `Cache-Control: private, max-age=31536000, immutable`로 브라우저 HTTP 캐시를 재사용합니다. 로그인은 필수이며 공개 전에는 출제자만 접근할 수 있습니다. 상태·오류 응답은 계속 `no-store`입니다. 미리보기는 로컬 그림을 사용해 서버 없이 동작합니다.

## 캐릭터 뽑기 운영

무료 코인은 한국 시간 00·03·06·09·12·15·18·21시에 요청이 오면 5개로 채웁니다. 남은 무료 코인과 놓친 충전은 이월하지 않습니다. 구매 코인은 1개 100G이며 한 번에 1개 또는 5개를 살 수 있고, 무료 코인을 먼저 씁니다. 인형 한 개당 1점·10G, 30개를 모두 뽑으면 추가 5점·300G를 지급합니다. 공개 경제 규칙은 `shared/balance.ts`의 `CLAW_RULES`를 사용합니다.

기계 조회는 저장된 판을 읽으며, bootstrap은 코인 요약만 제공합니다. 시뮬레이션은 새 플레이 요청에서 한 번 실행하고 재시도는 저장된 결과를 반환합니다. 화면 진입·플레이 후·화면 복귀·다음 충전 때만 조회하며 주기적으로 서버를 호출하지 않습니다. 응답이 끊기면 같은 요청 번호로 결과를 확인하고 코인을 중복 사용하지 않습니다. 미리보기는 서버 없이 같은 물리 엔진과 기기 메모리의 코인으로 동작합니다.

집게 힘 설정은 서버 DB의 `claw_config` 한 행에 있습니다. 운영 탭의 인형뽑기 카드에서 강집게 주기 1~50, 약집게 들어 올리는 힘·옮기는 힘 5~100%를 조정합니다. 변경은 `admin_changes`와 같은 batch에 저장하고 다음 플레이부터 적용합니다. 이미 저장된 플레이 결과는 그대로 재생합니다. 설정 전체는 운영 API에서만 반환하고 플레이어는 해당 판의 재생에 필요한 힘만 받습니다. 운영자 플레이도 개인 기계·재요청·대기 시간 규칙을 지키며 보상은 모두 0입니다.

물리 원본은 `iam-yeseo/yegoom@5a8017247c365b7233f4dfb2209a6bf27a30c678`이며 테스트 fixture와 완전 일치 검증을 유지합니다. 인형 출처·최적화·재생성 방법은 [자산 출처](docs/asset-provenance.md)에 기록했습니다. 원본 결과 장면 그림은 사용하지 않습니다.

## 운영 개선 PR 2 — 운영 탭과 게임 설정

PR #18 머지를 확인한 최신 main `f978282`에서 `codex/admin-console`로 시작했습니다. 운영 탭은 운영자만 보이며 플레이어의 직접 `#/admin` 진입은 홈으로 이동합니다. 운영 API는 서버에서 역할을 검사합니다.

예측 배점·참여/1등 골드·ON/OFF와 퇴근/행운 마감은 기본적으로 다음 날 KST 00:00부터 적용합니다. 오늘 예측과 정답이 모두 없을 때만 오늘 적용을 선택할 수 있고 서버가 같은 쓰기에서 다시 확인합니다. 판을 만들 때 당시 설정을 저장하여 이후 설정이 바뀌어도 정산·결과는 그 판의 설정을 유지합니다. OFF인 날에는 카드와 화면에 쉬는 날 안내를 표시하고 모든 입력·공개를 거절합니다.

**머지 전에 `npm run db:migrate:remote` 실행이 필요합니다.** `0009_admin_settings.sql`은 `game_settings`, `admin_changes`, nullable `game_rounds.settings_json`과 인덱스를 추가합니다. 기존 `0001`~`0008`은 수정하지 않습니다. 운영 반영은 리뷰 → 운영자 마이그레이션 → 머지·배포 순서입니다. 런칭 후이므로 `scripts/launch-reset.sql`은 변경하지 않았으며 새 설정·변경 기록 테이블을 초기화 대상으로 추가하지 않았습니다.

운영 미리보기는 `#/preview/admin`에서 들어갑니다. 예측 설정·집게 힘·운영자 기계는 메모리 안에서만 바뀌고 API를 호출하거나 실제 보상을 만들지 않습니다. 미리보기의 집게 힘은 운영 DB와 관계없는 예시 값입니다. 날짜별 규칙·읽기 비용·화면과 E2E 회차 의존성 보완은 [PR 2 검증 보고](docs/admin-console-validation.md)에 기록합니다.

검증: `npm run check`의 **615개 테스트**(Worker·D1 통합 262개 포함)·타입·빌드가 통과했습니다. 전체 E2E **69/69를 두 번 연속**, 지정한 캐치마인드 테스트는 390px·560px 각각 5회씩 **10/10** 통과했습니다. 실제 로그인·미리보기 화면 20장을 확인했고 기존 스크린샷 151장은 그대로 보존했습니다. 로컬 D1의 적용 설정 조회는 게임당 1행이며 과거 설정 200건을 더해도 증가하지 않습니다.

개선 PR 6은 새 마이그레이션이 없습니다. 추첨 시각 전환 배포는 **KST 17시 00분~17시 30분을 피해야 합니다**. 기존 17시 추첨과 추가 판매가 섞일 수 있는 이유와 반영 순서는 [로또 배포 안내](docs/lotto-rollout.md)를 따릅니다.

개선 PR 7은 **`0013_slot_machine.sql` 마이그레이션이 필요합니다**. 슬롯 기록 표와 인덱스만 추가하므로 기존 Worker 실행 중 먼저 적용할 수 있습니다. 순서는 리뷰 → 운영자 원격 마이그레이션 → 머지 → 배포입니다. 이번 작업에서는 원격 변경·머지·배포를 실행하지 않습니다. 출시 당시의 초기화 도구는 슬롯 기록을 지우지 않으므로 현재 서비스 전체 초기화에 사용하지 않습니다.
