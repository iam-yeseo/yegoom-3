### 1-2. 캐치마인드 지난 판 결과
- 지금은 새 판이 시작되면 직전 판 결과가 사라진다. 캐치마인드 화면에 **"지난 판" 카드**를 항상 보여 준다. 진행 중인 판과 별도다.
  - 회차(제 N판), 그림 썸네일, 정답, 그린 사람, 맞힌 사람(못 맞혔으면 "아무도 못 맞혔어요"), 끝난 시각
  - 누르면 1-3의 큰 보기 모달과 같은 모달이 열린다.
  - "갤러리 보기" 링크를 둔다.
- 지금 판이 끝난 상태(ended)라면 그 판 자체가 이미 결과로 보이므로, "지난 판"에는 그 이전 판을 보여 준다.
- 이름은 닉네임, 프로필 자리는 프로필 사진(없으면 캐릭터)을 쓴다.

### 1-3. 캐치마인드 갤러리
- 경로: `#/play/catchmind/gallery` (미리보기는 `#/preview/play/catchmind/gallery`). 캐치마인드 화면 위쪽과 "지난 판" 카드에서 들어간다.
- **끝난 판(ended)만** 보여 준다. 진행 중이거나 그리는 중인 판은 정답이 드러나므로 제외한다.
- **3×3 격자**, 최신 회차부터 보여 준다. 한 번에 9개씩 불러오고 "더 보기" 버튼(또는 스크롤 끝 자동 불러오기)으로 이어서 불러온다.
- 각 칸: 정사각형 그림 썸네일과 왼쪽 위 작은 "N판" 배지. 맞힌 판과 못 맞힌 판은 작은 표시로 구분한다.
- 칸을 누르면 **모달**로 크게 보여 준다: 회차, 큰 그림, 그린 사람, 정답, 맞힌 사람(또는 "아무도 못 맞혔어요"), 날짜, 닫기(바깥 누르기·Esc). 모달 안에서 이전·다음 판으로 넘길 수 있게 한다(좌우 버튼, 키보드 ←/→).
- 서버
  - `GET /api/catchmind/gallery?before=<회차>&limit=9` → 끝난 판의 메타데이터만 응답한다(회차, 판 id, 그린 사람, 정답, 맞힌 사람, 종료 사유, 끝난 시각, 이미지 주소). **그림 본문은 넣지 않는다.**
  - 이미지는 기존 `/api/catchmind/rounds/:id/image`(immutable 캐시)를 쓴다. 갤러리 썸네일 `<img>`에는 `loading="lazy"`와 고정 크기를 지정한다.
  - `catchmind_rounds(status, number)`에 인덱스가 없으면 추가형 마이그레이션으로 만든다. 요청 1회의 `rows_read`를 보고한다.
- 빈 상태: "아직 완성된 그림이 없어요. 첫 그림의 주인공이 되어 보세요!"
- 테스트: 진행 중 판 제외, 9개 단위 페이지, 회차 역순, 맞힘·못 맞힘 표시, 모달 이전·다음, 로그인 없이 401

## PR 2 (PR 1 머지 후)

### 2-1. 운영 탭
- **운영자(admin) 계정에만** 하단 탭에 "운영" 탭을 추가한다. 플레이어에게는 보이지 않고, 플레이어가 `#/admin`에 직접 들어오면 홈으로 보낸다. 서버의 모든 운영 API는 `role = 'admin'`만 허용한다(403).
- 탭이 6개가 되어도 390px에서 글자가 잘리지 않게 한다.
- 운영 화면 구성: "예측 게임" 카드 3개(기상·퇴근·행운 점수), "인형뽑기" 카드 1개, 화면 아래 "최근 변경 기록" 목록
- 모든 설정 변경은 `admin_changes(id, admin_id, target, before_json, after_json, effective_from, created_at)`에 남기고, 화면 아래 목록에 최근 20건을 보여 준다.

### 2-2. 예측 게임 설정
| 게임 | 조정 가능 항목 |
| --- | --- |
| 기상시간 | 배점표, 참여 골드, 1등 골드, ON/OFF |
| 퇴근시간 | 배점표, 참여 골드, 1등 골드, ON/OFF, **예측 마감 시각** |
| 행운 점수 | 배점표, 참여 골드, 1등 골드, ON/OFF, **예측 마감 시각** |

- **배점표 편집**: 행 단위(차이 기준 → 점수). 행 추가·삭제(1~10행)를 지원한다.
  - 검증: 기준은 오름차순이고 서로 달라야 한다. 점수는 0~100 정수이고 위에서 아래로 같거나 줄어들어야 한다. 기상·퇴근은 시·분·초 단위 입력, 행운 점수는 점수 차이 정수 입력이다.
  - 화면 표기는 기존 도움말과 같은 사람이 읽는 단위(1분 이내 등)로 미리보기한다.
- **골드**: 참여 0~1,000, 1등 0~10,000 정수
- **마감 시각**: `HH:MM:SS`. 행운 점수 마감은 자동 공개 시각(18:00:00)보다 앞이어야 한다. 기상시간 마감(10:30)은 바꾸지 않는다.
- **적용 시점 (중요)**: 이미 예측한 사람에게 규칙이 중간에 바뀌면 불공정하다. 그래서 **변경은 기본적으로 다음 날(KST 00:00)부터 적용**한다.
  - 오늘 판에 예측도 정답도 아직 없으면 "오늘부터 적용"을 고를 수 있다. 화면에서 선택지를 보여 주되, 활동이 있으면 비활성화하고 이유를 표시한다.
  - 서버는 저장할 때 오늘 활동 여부를 다시 확인한다(경쟁 상태 방지).
- **저장 구조**
  - `game_settings(game_id, effective_from, settings_json, created_at, created_by)`, PK `(game_id, effective_from)`
  - 날짜 D의 설정은 `effective_from <= D` 중 가장 최근 행이고, 없으면 지금의 `shared/balance.ts` 기본값이다.
  - `game_rounds`에 nullable `settings_json` 칸을 추가한다. 판이 처음 만들어질 때 그날 설정을 저장한다.
  - **정산은 그 판에 저장된 설정으로만** 한다. 판에 설정이 없는 기존 판은 그 날짜의 설정(=기본값)으로 한다.
  - 마감 검사(예측 저장의 SQL 조건 포함), 자동 공개 시각, 점수·골드 계산, 도움말·결과 칩·홈 카드 표시가 모두 이 설정을 읽어야 한다. `shared/balance.ts` 상수를 직접 쓰는 곳이 남지 않게 코드 전체를 확인하고 보고한다.
  - bootstrap의 각 게임에 `rules`(그날 적용 설정)를 넣어 화면이 서버 값을 쓰게 한다.
- **OFF인 날**
  - 홈·게임 탭 카드: "오늘은 쉬어요" 칩, 눌러도 게임 화면에 "오늘은 이 게임을 쉬어요" 안내만 보인다.
  - 서버: 예측·정답 입력·기상했어요·공개 요청을 409(`GAME_OFF`)로 거절하고 판을 만들지 않는다.
  - 최근 3판 기록은 공개된 판만 세므로 OFF인 날은 자연스럽게 건너뛴다.
- 테스트: 다음 날 적용, 활동 없는 날의 오늘 적용, 활동 있으면 오늘 적용 거절, 판 설정 스냅숏으로 정산(설정 변경 후에도 어제 판 점수 불변), 마감 변경 후 마감 검사, OFF 거절, 배점표 검증 실패 케이스, 플레이어 403

### 2-3. 인형뽑기 운영
- **운영자는 코인 없이 무제한으로 플레이**할 수 있다. 대신 **점수·골드·당첨 소식이 전혀 생기지 않는다**(ledger·announcements 기록 없음). 랭킹과 내역에도 나오지 않는다.
  - 운영자 전용 기계(`claw_accounts`의 운영자 행)를 쓴다. 판 진행·클리어·새 기계 생성은 플레이어와 똑같이 동작한다.
  - 연타 방지(`next_play_at`)는 유지한다.
  - 운영자 플레이 기록은 `claw_plays`에 남기되 점수·골드 0으로 저장한다.
  - 테스트용 옵션 "이번 판 강집게로"를 운영자에게만 제공한다(집게 힘 확인용).
- **집게 힘 조정**: 원본 yegoom `public/gatcha.html`의 운영자 설정을 참고해 운영 탭의 인형뽑기 카드에서 조정한다.
  - 강집게 주기 1~50, 약집게 들어 올리는 힘 5~100%, 약집게 옮기는 힘 5~100%
  - 슬라이더와 현재 값 표시, 원본의 설명 문구("플레이어마다 넣은 코인을 세어 정한 횟수째 판에 강집게…")를 그대로 쓴다.
  - 저장하면 **다음 플레이부터 즉시** 적용한다(이미 정해진 판 결과에는 영향 없음). `claw_config`를 업데이트하고 `admin_changes`에 남긴다.
  - 이 값은 운영 API 응답에만 담고, 플레이어 응답에는 절대 넣지 않는다(기존 원칙 유지).
- 테스트: 운영자 무제한 플레이와 보상 0, 운영자 플레이가 ledger·announcements를 만들지 않음, 강집게 옵션은 운영자만, 설정 범위 검증, 플레이어 403, 설정 변경이 다음 플레이에 반영

### 2-4. 마이그레이션
