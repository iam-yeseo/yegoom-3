# 구현의 범위와 결정

기준일: 2026-10-30 KST. 첨부 기획안은 변경 가능한 요구사항 자료로 사용했다. 기획안의 과거 지시인 “구현과 배포는 아직 시작하지 않는다”는 이번 사용자의 초기 구현 요청을 대체하지 않는다. 사용자는 구현 전에 **아이디·비밀번호 로그인**과 **기상·퇴근·행운 점수 실제 저장**을 선택했다.

2026-11-01 KST: PM 확정 [2차 계획](plan-v2.md)의 Phase 1~5를 반영했다. 문서 전체는 Phase 1 첫 커밋에 보존했다. Phase 2 PR #8이 main에 머지된 뒤 Phase 3 브랜치를 최신 main 위로 리베이스했으며 출석·캐릭터 저장·도움말 단위 표기를 모두 유지한다. Phase 5는 Phase 4 PR #10의 머지를 확인한 최신 main `18d26e7`에서 시작했다. 운영자가 `0005`를 원격 적용한 상태를 기준으로 하며 이번 작업은 Draft PR에서 멈춘다.

**작업 순서:** 다음 Phase는 반드시 이전 Phase PR의 main 머지를 확인한 뒤 시작한다. 미머지 상태이면 시작하지 않고 사용자에게 알린다.

## 확정하여 반영한 범위

React + TypeScript + Vite 클라이언트, 별도 Workers API, D1, PWA로 시작한다. 기존 `iam-yeseo/yegoom`의 데이터나 코드는 통째로 이관하지 않았다. KST 계산, 서버 권한과 마감 검사, API 캐시 제외라는 검증된 구조를 참고했다.

| 게임 | 출제자 | 예측 마감(KST) | 공개 방식 |
| --- | --- | --- | --- |
| 기상시간 | min | 10:30:00 | 확인 후 “기상했어요”를 누른 서버 시각을 초 단위 정답으로 즉시 공개 |
| 퇴근시간 | siwon | 17:00:00 | 입력한 초 단위 퇴근 시각에 자동 공개, 수동 조기 공개 가능 |
| 행운 점수 | yeseo | 17:00:00 | 18:00:00 자동 공개, 수동 조기 공개 가능 |

예측·정답은 당일 라운드에 저장한다. `roundDate`는 필수이며 서버의 오늘 날짜와 달라지면 저장을 거절한다. 출제자는 자신의 게임을 예측하지 못하고 운영자는 게임에 참여하지 못한다. 예측은 서버와 SQL 양쪽에서 마감·공개 상태를 검사한다. 정답은 출제자와 공개 후 조회에만 포함된다. 행운 점수 힌트는 공개 전에도 조회할 수 있다.

## 예측 게임 정책 — Phase 1 확정

출제자·마감·공개 시각·배점·보상은 `shared/balance.ts`를 단일 소스로 사용한다. Worker의 지급과 화면의 도움말·결과·미리보기가 같은 값을 읽는다.

- **입력:** 기상·퇴근은 `HH:MM:SS`만 받는다. `HH:MM`은 400으로 거절한다. 화면은 시·분·초 숫자를 직접 입력하거나 조절할 수 있는 입력을 사용한다.
- **기상시간 정답:** 클라이언트 시각을 무시하고 서버 시각을 기록·공개한다. 같은 날 재요청은 조건부 쓰기로 첫 정답을 보존하며 취소할 수 없다. 확인 시트를 거치고 공개 후 버튼을 숨긴다.
- **퇴근시간 자동 공개:** 미리 입력한 실제 퇴근 시각을 뜻한다고 해석했다. 이미 지난 시간을 입력하면 즉시 공개 상태가 된다.
- **조기 공개:** 공개 순간 예측을 닫는다. 공개된 정답의 변경도 막는다.
- **참여:** 게임별 첫 저장 순간 100G를 지급한다. 예측 수정·동시 저장에는 추가 지급하지 않는다.
- **정확도:** 각 게임의 차이(시간은 초)의 상한을 위에서부터 비교해 점수를 정한다. 0점은 원장 행을 만들지 않는다.
- **1등·동점:** 점수와 무관하게 차이가 가장 작은 예측자 모두 100G를 받는다. 예측자가 없으면 지급하지 않는다.
- **출제자 부재:** 예측 마감은 적용하되 정답이 없으면 결과를 대기 상태로 둔다. 정산하지 않고 먼저 받은 참여 보상은 유지한다.
- **주간 순위:** 점수와 순위만 표시하며 주간 골드 보상은 지급·표시하지 않는다.
- **기록:** 공개된 날만 세어 오늘을 제외한 최근 3판을 조회한다. 정답이 없는 날은 건너뛴다.
- **초기 골드·점수:** 지급 정책이 없으므로 원장의 합계 0을 보여 준다. 확정된 시작 잔액이 0이라는 뜻은 아니다.
- **계정 중지:** 기록과 원장을 보존하는 비활성화로 처리한다. 재생성/비밀번호 변경/권한 변경 시 기존 세션을 폐기한다.

## 출석과 캐릭터 선택 — Phase 2 확정

- **출석 저장:** `attendance(user_id, date, streak, created_at)`의 `(user_id, date)` PK로 서버 KST 하루 한 번 저장한다. 어제 출석했으면 연속 일수에 1을 더하고, 빠진 날이 있으면 1로 시작한다. 클라이언트 날짜·연속 일수·보상은 사용하지 않는다.
- **출석 지급:** `shared/balance.ts`의 규칙으로 7일째·14일째 등 7의 배수에는 500G, 그 밖에는 100G를 지급한다. 출석과 `attendance:<date>:<userId>` 원장 행을 같은 D1 batch에 기록하며 재시도·동시 요청은 한 번만 지급한다. 자정을 넘겨 DB 쓰기가 지연된 요청은 거절하고 현재 날짜로 다시 조회한다. 운영자는 출석할 수 없다.
- **출석 화면:** 화면의 n일째와 7칸은 달력 요일이 아닌 1~7일 주기로 표시한다. 월간 기록은 월별 서버 조회이며, 내 정보의 출석 수와 홈 잔액도 서버 데이터를 사용한다.
- **홈 접힘:** 완료 상태는 “오늘 출석 완료 · n일째” 한 줄이다. 새 출석을 받으면 기존 코인·캐릭터 점프가 끝난 뒤 접는다. 펼침은 즉시 높이를 바꾸고 opacity만 전환하며 reduced motion을 지킨다.
- **기기 출석 정리:** 기존 로그인 사용자의 localStorage 출석 키는 정리하고 서버로 옮기지 않는다. 미리보기 출석은 별도의 기기 데이터로 유지한다.
- **캐릭터 저장:** nullable `users.character`에 공통 `ArtKey` 8종 중 하나를 저장한다. null이면 min→axolotl, siwon→cat, yeseo→bunny, 나머지→monkey 기본값을 사용한다. 같은 캐릭터를 여러 플레이어가 선택할 수 있다. bootstrap과 공개 결과에 캐릭터를 포함해 랭킹·과거 기록의 아바타도 서버 선택을 따른다.
- **선택 이관:** 서버 값이 null일 때만 현재 기기의 기존 선택을 조건부로 한 번 가져온다. 이미 서버 값이 있으면 그대로 보존한다. 요청에 예상 사용자 ID를 검사해 다른 탭의 계정 변경이 이전 사용자의 선택을 새 계정에 가져오지 못하게 한다. 성공 후 기존 키를 지우고, 실패 시 재시도를 위해 보존한다. 미리보기 선택은 별도 localStorage 키를 사용한다.
- **예측 도움말 보완:** `SCORE_TABLES`의 차이 값을 시간·분·초로 변환해 “1분 이내”, “1시간 이내”처럼 표시한다. 행운 점수는 “N점 차이 이내”, 0은 기존 “정확히 일치”를 사용한다. 배점이나 기준값을 중복 정의하지 않는다.

## 상점 경제 — Phase 3 확정

- **공통 규칙:** 쿠지 가격·등급 수량·보상, 데일리 로또 추첨 시각·숫자 범위·당첨금, 스피또 확률·가격·당첨금은 `shared/balance.ts`에서 서버·화면·미리보기가 함께 읽는다.
- **구매와 이용권:** `shop_purchases`의 사용자별 고유 `requestId`로 구매를 식별한다. 조건부 쓰기에서 잔액·이용권·사용자 상태·서버 시각을 검사하고, 새 구매 ID에 종속된 차감·지급을 같은 D1 batch에 넣는다. 같은 요청은 저장된 결과를 돌려주며 다른 상품·내용으로 재사용하면 거절한다. 이용권은 수정·삭제를 막은 `inventory_ledger`의 합계다. 운영자는 구매할 수 없다.
- **예굼쿠지:** 모든 플레이어가 같은 100장 판을 사용하며 서버 crypto 난수로 등급을 섞는다. 미판매 칸의 등급은 응답에 넣지 않는다. 당일 개인 구매 수를 DB 쓰기 안에서 계산해 5장까지 300G, 6장째부터 400G로 차감한다. 여러 장 중 하나라도 판매됐거나 잔액이 부족하면 전부 실패한다. A~D는 점수·골드, E~H는 해당 이용권, 마지막 구매는 라스트원 1,000G를 추가 지급한다. 모두 팔린 다음 요청에서 새 판을 만든다. 점수 주차는 구매한 KST 날짜의 월요일이다.
- **데일리 로또:** 서로 다른 1~25 숫자 5개를 500G 또는 이용권 1장으로 산다. KST 17:00 전에는 당일, 이후에는 다음 날 추첨 표가 된다. 추첨 날짜 PK로 번호를 한 번만 저장하고 5/4/3/2개 일치에 5,000/3,000/1,000/500G를 지급한다. 구매 수 제한은 없다. 지난 미정산 날짜도 bootstrap·상점 요청에서 추첨·정산하며 같은 표에 두 번 지급하지 않는다. bootstrap은 잔액·내역 조회 전에 로또 정산을 완료하므로 상점을 열지 않아도 첫 응답에 당첨금이 반영된다.
- **스피또:** 300G 또는 이용권 1장을 사용한다. 서버 crypto 난수로 구매 순간 10% 당첨 여부와 기존 3칸 배치를 저장한다. 당첨은 같은 캐릭터 3개, 낙첨은 3개가 일치하지 않으며 당첨금 1,500G를 구매 batch에서 지급한다. 긁기·나가기·재접속은 결과나 잔액을 바꾸지 않는다.
- **요청 경계:** 본문을 읽은 후 서버 시각을 잡고 DB 쓰기에서도 날짜·추첨 회차 경계를 검사한다. 응답이 유실된 구매는 기기의 사용자별 세션 저장소에 같은 요청 내용을 보관해 재확인한다. 성공한 구매는 후속 잔액 조회가 실패해도 실패로 바꾸지 않는다.
- **화면:** 상점·로또·스피또에 이용권 수량과 결제 선택을 표시한다. 쿠지 등급·라스트원 보상은 기존 시트 스타일의 모달로 안내하며 닫기·바깥 클릭·Esc를 지원한다. 미리보기는 독립적인 메모리 상태로 서버 없이 같은 경제 규칙을 체험한다. 미리보기의 출석 보상과 상점 결제는 같은 잔액을 사용하며 날짜가 바뀌어도 이미 받은 보상을 회수하지 않는다.

## 캐치마인드 — Phase 4 확정

- **판과 차례:** 날짜를 바꾸어도 진행 중인 판을 유지한다. 처음에는 플레이어 누구나 차례를 맡을 수 있으며, 그 뒤에는 정답자에게 다음 차례가 넘어간다. 오답 6개 또는 출제자의 직접 종료에는 보상 없이 기존 출제자가 차례를 유지한다. 끝난 판은 결과로 남겨 두고 다음 출제자가 새 판을 시작할 때 교체한다. 운영자는 조회만 한다.
- **제시어:** `shared/catchmind-words.ts`의 400개는 기존 [skatch-mind-words.js](https://github.com/iam-yeseo/yegoom/blob/main/src/lib/skatch-mind-words.js)에서 가져왔다. 원본 blob은 `4c4b07dc9e46e03da98434965e293d9c6c81e9d4`다. 서버 crypto 난수로 선택하고 출제자에게만 전달한다. 공개 전에 3회 바꿀 수 있으며 같은 판에서 이미 받은 단어는 다시 나오지 않는다. `wordVersion` 검사는 바꾸기 전 제시어로 작성한 그림의 뒤늦은 저장을 막는다. bootstrap에는 공개 전 정답과 그림을 넣지 않는다.
- **답과 정산:** 공백만 제거해 비교하며 대소문자나 유니코드 정규화 규칙을 추가하지 않는다. 답변은 모두 공개되고 오답 3개부터 첫 글자·글자 수 힌트를 보여 준다. 첫 정답자에게 힌트 여부와 무관하게 3점·5G를 지급한다. 요청 기록·답변·종료·다음 차례·원장 지급을 한 D1 batch에 묶는다. 같은 `requestId`는 오답 횟수나 보상을 늘리지 않고, 다른 내용으로 재사용하면 거절한다. 동시 정답에서도 한 사람만 지급받는다. 원장 reference는 `catchmind:score:<roundId>`, `catchmind:gold:<roundId>`다.
- **게임 날짜:** 날짜 구분 없이 이어지는 판의 점수 기준일은 그림을 공개한 서버 KST 날짜로 정한다. 다음 주에 정답을 맞혀도 그 날짜가 속한 월요일을 `week_start`로 사용한다. 일별 점수 그래프도 지급일 대신 공개일에 합산한다. 출제 본문을 읽은 뒤 서버 시각을 잡고 SQL에서도 날짜 경계를 확인한다.
- **그림:** 공개한 그림은 수정할 수 없다. PNG 또는 WebP data URL을 저장하며 “300KB”는 디코딩된 이미지 바이트 300KiB(307,200바이트)로 적용한다. 큰 JSON 본문 허용은 출제 경로에만 한정한다. 선언된 MIME과 실제 PNG/WebP 서명·청크·정사각형 양수 크기를 확인하고, PNG 청크 CRC도 검사한다.
- **도구와 컬러 피커:** 의존성을 추가하지 않고 펜·지우개·스캔라인 영역 채우기·실행 취소를 구현한다. 컬러 피커는 가로 채도·세로 명도, 색상, 투명도, HEX 입력, 견본·최근 색 5개를 제공하며 포인터·터치·키보드를 지원한다. 투명도는 펜에 적용하고 채우기는 불투명으로 처리한다. 브라우저 지원 범위 때문에 스포이드는 넣지 않고, RGB/CSS/HSL 출력 형식 선택도 제외한다. 캔버스와 피커의 `data-notouchfx`는 전역 터치 이펙트에서 제외한다.
- **갱신과 미리보기:** 화면이 보이는 동안 5초마다 조회하고 숨겨지면 멈춘다. `#/preview`는 서버 없이 독립 상태로 같은 판 진행을 체험하며 실제 사용자 기록·원장에 쓰지 않는다. 기존 디자인 토큰과 reduced motion 규칙을 유지한다.

## 전역 터치 이펙트 — Phase 5 확정

- **표현과 설치:** `src/motion.ts`의 `installTouchEffect()`를 버튼 눌림 피드백과 함께 한 번 설치한다. 기존 `fxLayer()`에서 작은 원과 앱 팔레트 색 점 4개를 표시하며 전체 크기는 최대 44px, 수명은 400ms 이하다. transform·opacity만 움직인다. 기본 대화상자 안에서는 해당 효과만 임시 manual popover로 올려 가려지지 않게 하며 포커스와 클릭은 그대로 통과시킨다.
- **입력과 제한:** 주 포인터의 `pointerdown`만 받으며 마우스는 왼쪽 버튼만 허용한다. passive 리스너로 스크롤·드래그를 방해하지 않는다. 60ms 이내 연속 입력을 무시하고 동시에 남는 이펙트는 최대 8개로 제한한다.
- **제외:** reduced motion에서는 노드를 만들지 않는다. `input`, `textarea`, `select`, `canvas`, `[contenteditable]`, `[data-notouchfx]`와 내부 요소에서도 만들지 않아 입력·그림·피커 조작을 유지한다.
- **캐치마인드 이미지 보완:** 저장된 data URL은 유지하되 상태 응답의 `image`에는 판 ID별 URL만 넣는다. `GET /api/catchmind/rounds/:id/image`는 로그인과 공개 전 출제자 권한을 검사한 뒤 PNG/WebP 바이트를 반환한다. `Cache-Control: private, max-age=31536000, immutable`로 바뀌지 않는 그림을 브라우저 HTTP 캐시에서 재사용하고 `Vary: Cookie`로 로그인 세션별 캐시를 구분한다. 서비스 워커의 `/api` 캐시 제외 규칙은 그대로 유지한다. 미리보기의 로컬 그림은 서버에 요청하지 않는다.

## 저장과 정산의 경계

`users`, `sessions`, `login_attempts`, `game_rounds`, `predictions`, `attendance`, `ledger`를 분리했다. 세션 토큰은 서버에 SHA-256 해시만 저장하고 비밀번호는 무작위 salt를 사용하는 PBKDF2로 저장한다. API 상태·오류 응답은 `no-store`이며, 캐치마인드 이미지에만 위 private HTTP 캐시 정책을 적용한다. 수정 요청은 Origin 검사와 서버 권한 검사를 통과해야 한다.

골드·점수 원장은 append-only이며 각 지급에 중복 방지용 UNIQUE `reference`를 둔다. 예측은 `predict:<game>:<date>:<userId>`, 정확도 점수는 `score:<game>:<date>:<userId>`, 1등은 `first:<game>:<date>:<userId>`다. `INSERT OR IGNORE`와 D1 batch로 중복을 막고 정정은 반대 방향의 새 행으로 기록한다. 정산의 지급 행과 `settled_at` 표시는 한 batch에 기록한다.

bootstrap·게임·기록 조회는 공개된 미정산 판을 멱등 정산한다. 늦게 조회한 과거 판도 대상이며, 점수 행의 `week_start`는 반드시 **게임 날짜가 속한 KST 월요일**이다. bootstrap은 정산 후 잔액·순위·내역을 읽으므로 첫 조회에도 지급 결과가 보인다. 새 주가 되어도 골드나 이전 결과를 삭제하지 않는다.

Phase 1의 `0002`는 정산 표시, Phase 2의 `0003_attendance_characters.sql`은 출석 테이블과 nullable 캐릭터 컬럼, Phase 3의 `0004_shop_economy.sql`은 상점 경제 테이블을 추가했다. Phase 4의 `0005_catchmind.sql`은 판·차례·답변·요청 기록 테이블을 추가했다. Phase 5는 스키마 변경이 없으며 `0001`~`0005`도 수정하지 않는다. 운영자가 `0005`까지 적용한 상태에서 **리뷰·머지 → 배포** 순서로 반영한다. 이번 작업은 Draft PR에서 멈추며 원격 DB 변경·머지·배포를 실행하지 않는다.

이번 Phase에서 구현하지 않는 범위는 다음과 같다. 후속 Phase에서 확정된 항목은 `plan-v2.md`를 따른다.

- 초기 잔액·월간 보상
- 뽑기 비용·일일 횟수·성공률, 주식 종목·공휴일 캘린더·시세·정산
- 여섯 번째 정규 게임
- 캐릭터의 최종 애니메이션 도구와 방 꾸미기 범위
- 운영자 웹 화면, 비밀번호 찾기, 로그인 추가 보안 정책

쿠지의 조건부 구매 기록과 후속 쓰기는 기존 `iam-yeseo/yegoom`의 `src/lib/kuji.js`, `src/routes/kuji.js`, `src/lib/shop.js`에서 패턴을 참고했다. 코드를 통째로 옮기거나 그 저장소의 다른 경제 규칙을 가져오지 않았다.

## 화면에 표시하는 잠정값

예측 게임·출석·쿠지·데일리 로또·스피또·캐치마인드는 서버의 실제 규칙으로 표시하고 원장에 지급한다. 주간 순위 보상 표시는 제거했다. 뽑기 등 서버화하지 않은 화면은 기존 범위를 유지한다. `src/sample.ts`의 `BALANCE`는 미리보기용으로 유지하되 예측 게임·출석·상점·캐치마인드와 겹치는 값은 `shared/balance.ts`를 참조한다.
