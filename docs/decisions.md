# 초기 구현의 범위와 결정

기준일: 2026-10-30 KST. 첨부 기획안은 변경 가능한 요구사항 자료로 사용했다. 기획안의 과거 지시인 “구현과 배포는 아직 시작하지 않는다”는 이번 사용자의 초기 구현 요청을 대체하지 않는다. 사용자는 구현 전에 **아이디·비밀번호 로그인**과 **기상·퇴근·행운 점수 실제 저장**을 선택했다.

## 확정하여 반영한 범위

React + TypeScript + Vite 클라이언트, 별도 Workers API, D1, PWA로 시작한다. 기존 `iam-yeseo/yegoom`의 데이터나 코드는 통째로 이관하지 않았다. KST 계산, 서버 권한과 마감 검사, API 캐시 제외라는 검증된 구조를 참고했다.

| 게임 | 출제자 | 예측 마감(KST) | 초기 공개 방식 |
| --- | --- | --- | --- |
| 기상시간 | min | 10:30 | 출제자가 직접 공개 |
| 퇴근시간 | siwon | 17:00 | 입력한 퇴근 시각에 자동 공개, 수동 조기 공개 가능 |
| 행운 점수 | yeseo | 17:00 | 18:00 자동 공개, 수동 조기 공개 가능 |

예측·정답은 당일 라운드에 저장한다. `roundDate`는 필수이며 서버의 오늘 날짜와 달라지면 저장을 거절한다. 출제자는 자신의 게임을 예측하지 못하고 운영자는 게임에 참여하지 못한다. 예측은 서버와 SQL 양쪽에서 마감·공개 상태를 검사한다. 정답은 출제자와 공개 후 조회에만 포함된다. 행운 점수 힌트는 공개 전에도 조회할 수 있다.

## 잠정 정책 — 추후 변경 가능

다음은 미정인 기획을 영구 확정한 것이 아니라 이번 저장 기능이 모순 없이 동작하기 위한 초기 정책이다.

- **기상시간 정답:** 직접 입력하고 수동 공개한다.
- **퇴근시간 자동 공개:** 미리 입력한 실제 퇴근 시각을 뜻한다고 해석했다. 이미 지난 시간을 입력하면 즉시 공개 상태가 된다.
- **조기 공개:** 공개 순간 예측을 닫는다. 공개된 정답의 변경도 막는다.
- **출제자 부재:** 예측 마감은 적용하되 정답이 없으면 결과를 대기 상태로 둔다. 보상을 지급하거나 판을 임의 취소하지 않는다.
- **동점:** 현재 결과는 오차 비교만 표시한다. 동점의 지급 우선순위나 주간 동점 보상을 정하지 않는다.
- **초기 골드·점수:** 지급 정책이 없으므로 원장의 합계 0을 보여 준다. 확정된 시작 잔액이 0이라는 뜻은 아니다.
- **계정 중지:** 기록과 원장을 보존하는 비활성화로 처리한다. 재생성/비밀번호 변경/권한 변경 시 기존 세션을 폐기한다.

## 저장과 정산의 경계

`users`, `sessions`, `login_attempts`, `game_rounds`, `predictions`, `ledger`를 분리했다. 세션 토큰은 서버에 SHA-256 해시만 저장하고 비밀번호는 무작위 salt를 사용하는 PBKDF2로 저장한다. API 응답은 `no-store`; 수정 요청은 Origin 검사와 서버 권한 검사를 통과해야 한다.

골드·점수 원장은 append-only이며 각 지급에 중복 방지용 `reference`를 둔다. 정정은 반대 방향의 새 행으로 기록하도록 설계했다. 주간 점수는 KST 월요일의 `week_start`를 집계하므로 새 주가 되어도 골드나 이전 결과를 삭제하지 않는다. 아직 지급·차감/정산 API는 노출하지 않는다.

밸런스를 추가할 때는 적용 시점과 버전을 정산 기록에 연결해야 한다. 다음은 미정 상태로 남겼다.

- 출석·참여·1등·주간 보상액, 초기 잔액, 정확도별 배점, 월간 보상
- 쿠지 가격·누진식·등급 구성·판 교체, 로또·스피또 가격/확률/보상
- 뽑기 비용·일일 횟수·성공률, 주식 종목·공휴일 캘린더·시세·정산
- 캐치마인드 실패 횟수·힌트와 점수, 여섯 번째 정규 게임
- 캐릭터의 최종 애니메이션 도구와 방 꾸미기 범위
- 운영자 웹 화면, 비밀번호 찾기, 로그인 추가 보안 정책

쿠지·뽑기의 서버 구현 시 기존 yegoom에서 확인한 요청 ID, 조건부 D1 배치, UNIQUE 제약을 참고해 중복 구매·중복 지급을 방지할 수 있다. 화면 단계의 로컬 로직을 그대로 경제 시스템에 연결해서는 안 된다.

## 화면에 표시하는 잠정값

시안을 그대로 재현하기 위해 결과 화면의 점수·참여 골드·1등 보너스, 주간 순위 보상, 출석 보상, 뽑기·쿠지·로또·스피또 가격을 표시한다. 이 값은 확정이 아니며 원장에 지급되지 않는다. 모두 `src/sample.ts`의 `BALANCE` 한 곳에서 바꾼다. 정산을 구현할 때는 서버 규칙으로 옮기고 화면은 서버 값을 표시하도록 바꾼다.
