### 1-2. 공정성 원칙 (모든 PR 공통)

1. **미래 정보는 아무에게도 보이지 않는다.** 공개 시각 전의 뉴스, 예정된 가격 이벤트, 난수 시드는 플레이어 API와 **운영자 API 모두**에서 내려주지 않는다. 운영 탭에도 표시하지 않는다.

## 3. 장 운영과 휴장

1. **장 시간:** 평일 09:00~18:00 KST(지금 미리보기의 `marketOpen()`과 같음). 18:00 가격이 그날 종가다.
2. **휴장일:** 주말 + 공휴일 + 운영자가 추가한 임시 휴장일.
   - `shared/market-calendar.ts`에 공휴일 목록을 둔다. 2026년 남은 공휴일은 12월 25일. 2027년 목록(설·추석 연휴, 대체공휴일 포함)은 **공식 자료(우주항공청·한국천문연구원 특일 정보 등)를 확인해서** 채우고 출처를 주석으로 남긴다. 기억에 의존해 날짜를 넣지 않는다.
   - `market_holidays(date PK, reason, created_by, created_at)` 표에 운영자가 임시 휴장일을 추가·삭제한다(선거일·임시공휴일 대비). 이미 장이 열린 오늘은 추가할 수 없다.
   - 연말 휴장(12월 31일)은 넣지 않는다(결정).
3. **예굼(YEGM) 겨울 근무:** 12월·1월·2월에는 **수요일에만** 거래한다(결정). 그 밖의 날에는 `거래 정지 · 겨울 근무 중` 배지를 보여 주고, 가격도 움직이지 않는다.
4. 휴장일에는 가격·뉴스·AI 호출이 모두 없다.

## 4. 가격 엔진

### 4-1. 데이터

```sql
-- migrations/00xx_stock_market.sql (번호는 그때 main의 다음 번호)
CREATE TABLE stock_state (            -- 종목별 현재 상태 10행
  ticker TEXT PRIMARY KEY,
  price INTEGER NOT NULL CHECK (price >= 1),
  prev_close INTEGER NOT NULL,        -- 상·하한가 기준
  day_open INTEGER, day_high INTEGER, day_low INTEGER,
  status TEXT NOT NULL CHECK (status IN ('listed','warning','delisted','halted')),
  warning_since TEXT,                 -- 관리종목 지정일
  delisted_on TEXT, relist_on TEXT,
  last_tick_at INTEGER NOT NULL,
  version INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE stock_ticks (            -- 10분 가격, 최근 30일만 보관
  ticker TEXT NOT NULL, at INTEGER NOT NULL, price INTEGER NOT NULL,
  PRIMARY KEY (ticker, at)
);
CREATE TABLE stock_daily (            -- 일봉, 계속 보관
  ticker TEXT NOT NULL, date TEXT NOT NULL,
  open INTEGER NOT NULL, high INTEGER NOT NULL, low INTEGER NOT NULL, close INTEGER NOT NULL,
  PRIMARY KEY (ticker, date)
);
CREATE TABLE stock_events (           -- 가격에 영향을 주는 사건
  id TEXT PRIMARY KEY,
  ticker TEXT NOT NULL,
  kind TEXT NOT NULL,                 -- news | rumor | rumor_confirm | rumor_denied | game | mosquito | relist | delist | warning
  effect_bp INTEGER NOT NULL,         -- 가격 변화, 1bp = 0.01%
  apply_at INTEGER NOT NULL,          -- 반영(=뉴스 공개) 시각, 10분 단위
  applied_at INTEGER,
  context_json TEXT NOT NULL,         -- AI·템플릿에 줄 사실(예: 기상 07:42, 평소보다 38분 일찍)
  created_at TEXT NOT NULL
);
CREATE INDEX stock_events_due_idx ON stock_events(applied_at, apply_at);
```

### 4-2. 움직이는 방법

- **주기:** 장 중 10분마다(09:10, 09:20 … 18:00). 하루 54번.
- **Cron Trigger는 하나만** 둔다: 10분마다 실행(`*/10 * * * *`). 핸들러가 KST 날짜·시각·휴장 여부를 보고 할 일을 정한다. Cron이 한 번 빠져도 다음 실행에서 **빠진 틱을 순서대로 모두 계산**한다(한 번에 최대 60틱).
- **한 틱의 변화:** `수익률 = 평균 회귀 + 변동성 × 표준정규난수 + 이번 틱에 반영할 이벤트 합`
  - 변동성(10분 기준, 결정·조정 가능): 안정 0.35%, 보통 0.6%, 급등락 1.0%
  - 평균 회귀: 기준가 쪽으로 아주 약하게 당긴다(`κ × ln(기준가 / 현재가)`, κ 기본 0.02). 기준가는 상장가에서 시작해 주 단위로 천천히 움직인다. 목표는 **10종목 기준 상장폐지가 한 달에 0~2건 정도** 나오는 것이다. Vitest에서 1,000번 모의실험(20거래일)을 돌려 상수를 맞추고 결과 분포를 PR에 적는다.
  - 난수는 `HMAC(STOCK_SEED_SECRET, 날짜|티커|틱번호)`로 만든다. 같은 입력이면 같은 결과이므로 Cron 재실행·빠진 틱 보충이 안전하다.
- **상·하한가:** 하루 등락은 전날 종가 대비 **±15%**로 제한한다(지금 화면의 `LIMIT`). 이벤트도 이 안에서만 반영된다. 화면 배지 `상한가`/`하한가`.
- 가격은 1G 단위 정수, 최소 1G.
- 다음 거래일 시가 = 전날 종가. 밤사이 생긴 게임 연동 이벤트(§7)는 09:00 첫 틱에 반영한다(갭).
- 쓰는 행: 틱 10×54 + 상태 갱신 ≈ 하루 1,100행 이내. 30일 지난 `stock_ticks`는 하루 한 번 지운다(일봉은 `stock_daily`에 남는다).

## 5. 매매

1. 장 중에만, 1주 단위, 한 주문 1~500주. 종목당 보유 최대 **500주**.
2. 체결가 = 요청 시점의 `stock_state.price`(SQL 안에서 읽는다). 화면에서 본 가격과 다르면(그사이 틱이 지남) 응답에 실제 체결가를 보여 준다. 화면이 보낸 `expectedVersion`과 `stock_state.version`이 다르면 409를 주고 새 가격으로 다시 확인받게 한다.
3. **수수료 1%**(올림, 최소 1G). 매수: `가격×수량 + 수수료` 차감, 매도: `가격×수량 − 수수료` 지급. 골드는 기존 `ledger`에 쓴다(사유 `주식 매수 · YK하이커스 10주`, `주식 매도 · …`; reference `stock:buy|sell:<userId>:<requestId>`). 잔액 검사는 PR 2의 잔액 캐시를 쓴다.
4. 표:
   ```sql
   CREATE TABLE stock_holdings (user_id TEXT NOT NULL REFERENCES users(id), ticker TEXT NOT NULL,
     quantity INTEGER NOT NULL CHECK (quantity >= 0), cost_basis INTEGER NOT NULL CHECK (cost_basis >= 0),
     PRIMARY KEY (user_id, ticker));
   CREATE TABLE stock_trades (id TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id), request_id TEXT NOT NULL,
     ticker TEXT NOT NULL, side TEXT NOT NULL CHECK (side IN ('buy','sell','delist')),
     quantity INTEGER NOT NULL, price INTEGER NOT NULL, fee INTEGER NOT NULL, total INTEGER NOT NULL,
     date TEXT NOT NULL, created_at TEXT NOT NULL, UNIQUE (user_id, request_id));
   ```
   `cost_basis`는 보유 주식을 사는 데 쓴 골드 합(수수료 포함). 평균 단가 = `cost_basis / quantity`. 매도 시 비율만큼 줄인다.
5. 같은 `requestId` 재요청은 처음 결과를 그대로 돌려준다. 잔액·보유·장 시간·종목 상태·버전 검사와 원장·보유·거래 기록을 **한 `db.batch`**에서 조건부로 처리한다(상점의 기존 패턴).
6. 거절: 장 마감·휴장, 거래 정지(예굼 겨울), 상장폐지 종목, 잔액 부족, 보유 부족, 500주 초과, 운영자, 출제자 제한(§7-3).
7. **주식 수익은 랭킹 점수에 넣지 않는다.** 골드에만 반영된다.

## 6. 상장폐지와 재상장

**사용자 결정:** 상장가의 **80%** 아래로 떨어지면 상장폐지.

**결정(판단 방식):** 장중 순간 가격이 아니라 **종가 기준**으로 판단하고, 하루 경고를 거친다.
1. 18:00 종가가 상장가의 80% 미만이면 **관리종목** 지정(`status='warning'`, 배지 `관리종목`, 템플릿·AI 공시 뉴스).
2. 다음 거래일 종가도 80% 미만이면 **상장폐지**. 80% 이상으로 회복하면 관리종목 해제(공시 뉴스).
3. 상장폐지 시: 그 종목 보유 수량은 0이 되고 돌려받는 골드는 없다. 각 보유자에게 `stock_trades`에 `side='delist'` 기록을 남겨 내역에 보이게 한다. 원장은 건드리지 않는다. 화면은 지금 있는 상장폐지 화면을 쓴다.
4. **재상장:** 상장폐지 후 **10거래일** 뒤 09:00에 상장가로 다시 상장한다(공시 뉴스 `재상장`). 기준가도 상장가로 되돌린다.
5. 상·하한가 ±15%이므로 상장가에서 80% 아래로 내려가려면 최소 2거래일이 걸린다. 위 모의실험에서 관리종목·상장폐지 빈도도 함께 기록한다.

## 7. 게임 결과 연동 (PR 11)

### 7-1. 규칙

| 종목 | 연동 | 효과 (결정·상수로 조정 가능) |
| --- | --- | --- |
| MINJ | 기상시간 정답(출제자 min) | 평소 기상 시각보다 일찍 일어나면 상승. 30분 일찍마다 +4%, 최대 ±8% |
| SIWN | 퇴근시간 정답(출제자 siwon) | 평소 퇴근 시각보다 일찍 퇴근하면 상승. 30분마다 ±4%, 최대 ±8% |
| YEDO | 행운 점수 정답(출제자 yeseo) | `(점수 − 50) / 50 × 8%` → 100점 +8%, 50점 0%, 0점 −8% |
| YEGM | 모기 사냥(무작위) | 거래일마다 0~2번. 성공 55%: +5~12%, 실패: −5~12% |

- "평소" = 그 게임의 최근 공개된 14판(오늘 제외) 정답의 중앙값. 3판 미만이면 기상 08:00:00, 퇴근 18:00:00.
- 출제자는 `GAME_RULES[game].author`(지금 min·siwon·yeseo)에서 읽는다. 하드코딩하지 않는다.
- 그날 게임이 OFF이거나 정답이 없으면 이벤트가 없다.

### 7-2. 반영 시점

- 정답 공개가 **장 중**이면 공개 직후 다음 10분 틱이 아니라 **공개 처리와 같은 요청에서** `apply_at = 지금`인 이벤트를 만들고 즉시 가격·뉴스를 반영한다(뉴스 공개와 가격 반영이 같은 순간).
- 정답 공개가 **장 밖**이면(기상은 보통 09:00 전, 퇴근은 18:00 뒤, 행운은 18:00 공개) 다음 거래일 09:00 첫 틱에 반영한다. 모두가 결과를 이미 알지만 장이 닫혀 있어 미리 살 수 없으므로 공정하다.
- 기존 공개 흐름(`worker/index.ts`의 정답 저장·공개·기상 처리)에 훅을 넣되, 주식 처리 실패가 게임 공개를 막으면 안 된다(주식 이벤트 쓰기를 같은 batch에 넣을 수 없으면, 다음 Cron이 공개된 판을 보고 이벤트를 만들도록 멱등하게 구성: reference `game:<gameId>:<date>`).

### 7-3. 출제자 매매 제한

- 출제자는 **자기 연동 종목**을 그날 00:00부터 그 이벤트가 가격에 반영될 때까지 사고팔 수 없다(매수·매도 모두). 퇴근·행운은 대개 다음 거래일 09:00까지 이어진다.
- 화면: 그 종목 상세에서 버튼 대신 `오늘은 출제자라서 거래할 수 없어요 · 결과 반영 후 거래 가능`.

## 8. AI 뉴스 (PR 12)

### 8-1. 기본 구조

- **AI는 글만 쓴다.** 어떤 종목이 언제, 어느 방향으로, 얼마나 움직일지는 서버(§4·§7, `stock_events`)가 먼저 정한다. AI는 그 사건에 맞는 제목·본문만 만든다. AI 출력의 숫자로 가격을 바꾸지 않는다.
- **AI가 실패해도 게임은 돈다.** 키 없음·오류·시간 초과·거절(refusal)·형식 오류·예산 초과면 `shared/stock-news-templates.ts`의 템플릿 문장으로 대신한다. 템플릿은 사건 종류×방향별로 종목마다 2~3개씩 미리 써 둔다(시트 소개 문구의 장난스러운 말투).
- 표:
  ```sql
  CREATE TABLE stock_news (
    id TEXT PRIMARY KEY, event_id TEXT REFERENCES stock_events(id), ticker TEXT,
    kind TEXT NOT NULL,            -- news | rumor | confirm | denied | game | mosquito | whale | disclosure | close | weekly
    publish_at INTEGER NOT NULL, headline TEXT NOT NULL, body TEXT NOT NULL,
    audience_user_id TEXT,         -- 개인 코멘트만 값이 있음(본인에게만 보임)
    source TEXT NOT NULL CHECK (source IN ('ai','template')),
    hidden INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL);
  CREATE INDEX stock_news_publish_idx ON stock_news(publish_at);
  CREATE TABLE ai_usage (date TEXT PRIMARY KEY, calls INTEGER NOT NULL DEFAULT 0,
    input_tokens INTEGER NOT NULL DEFAULT 0, output_tokens INTEGER NOT NULL DEFAULT 0,
    cache_write_tokens INTEGER NOT NULL DEFAULT 0, cache_read_tokens INTEGER NOT NULL DEFAULT 0,
    cost_micro_usd INTEGER NOT NULL DEFAULT 0);
  ```
- 모든 뉴스 조회 API는 `publish_at <= 지금 AND hidden = 0`인 것만, 개인 코멘트는 본인 것만 내려준다. **운영자 API도 같다.**

### 8-2. 언제 무엇을 만드는가

| 시점 | 내용 | 호출 |
| --- | --- | --- |
| 거래일 08:50 Cron | 오늘의 예정 사건 8~12개(일반 호재·악재, 찌라시 1~2개와 그 확인/부인 보도, 모기 사냥)를 서버가 정하고, 그 전부의 기사를 **한 번에** 생성 | 1회 |
| 장 중 사건 발생 | 게임 연동 속보(§7), 큰손 소식(§8-4) | 사건마다 1회 |
| 18:00 Cron | 오늘의 시황 요약 1개 + 플레이어별 한 줄 코멘트(보유 종목·손익 기반, 본인에게만) | 1회 |
| 금요일 18:00 | 주간 실적 발표(종목별 한 주 성적과 다음 주 전망, 전망은 재미용이며 가격과 무관) | 1회 |

**찌라시:** 서버가 찌라시를 만들 때 사실 여부(사실 60%, 결정)와 확인 시각(2~4시간 뒤)을 함께 정한다. 찌라시 공개 시 ±2~3%, 확인 보도 시 사실이면 같은 방향 ±4~8%, 거짓이면 찌라시 효과를 되돌리고 반대 방향 1~2%. 아침 한 번의 호출에서 찌라시와 그 결말 기사를 같이 만들어 이야기가 이어지게 한다. 화면에는 `[찌라시]` 라벨, 확인 보도에는 원래 찌라시 링크.

### 8-3. Claude API 호출

- **SDK:** `@anthropic-ai/sdk`(Workers에서 동작). 키는 `wrangler secret put ANTHROPIC_API_KEY`로 Worker 비밀값에 둔다. `.dev.vars`/`.env.example`에는 이름만 적는다. 키가 없으면 템플릿만 쓴다(로컬·테스트 기본).
- **모델:** `claude-opus-5-5`. `output_config.effort`는 `"medium"`으로 명시한다.
- **구조화 출력:** `output_config.format`에 JSON 스키마를 넣어 `{ items: [{ eventId, headline, body }] }`처럼 받는다. 서버에서 다시 검증한다: 요청한 `eventId`와 정확히 일치, 제목 40자·본문 200자 이내, 허용 종목명만 등장, 금지어 목록 미포함. 실패한 항목만 템플릿으로 바꾼다.
- **거절 대비:** `stop_reason === "refusal"`을 먼저 확인한다. 서버 측 대체 모델 기능(`fallbacks: "default"`, 베타 헤더 `server-side-fallback-2026-07-01`)을 켠다. 그래도 거절이면 템플릿.
- **SDK 사용법은 추측하지 말고** 공식 SDK 문서·저장소에서 위 기능(structured outputs, beta 헤더, fallbacks, prompt caching, 오류 클래스)의 TypeScript 사용법을 확인해 쓴다.
- **프롬프트 캐시:** 매번 같은 부분(세계관, 10개 회사 소개, 말투·안전 규칙, 예시 기사)을 시스템 프롬프트 앞부분에 고정하고 캐시를 켠다. 날짜·사건 목록처럼 바뀌는 내용은 그 뒤 사용자 메시지에 둔다. 응답의 `usage.cache_read_input_tokens`로 캐시가 맞는지 확인한다.
- **입력에 넣는 것:** 사건 목록(티커, 방향, 크기 구간 `작게/보통/크게`, 종류, 게임 연동이면 사실 정보), 최근 공개 기사 제목 20개(반복 방지), 오늘 날짜·요일. **정확한 퍼센트는 기사에 쓰지 말라**고 지시한다(화면이 실제 등락률을 따로 보여 준다).
- **말투·안전 규칙(시스템 프롬프트):** 짧은 한국어 경제 기사 패러디, 시트 소개 문구처럼 엉뚱하고 장난스럽게. 멤버 닉네임은 써도 되며 뒤에 "님"(§1-1). 외모·건강·연애·실제 직장·가족 등 사적인 내용, 욕설, 실존 기업·실제 사건·정치·재난은 쓰지 않는다. 투자 권유 문구(사라/팔아라) 금지.
- **호출 위치:** Cron 핸들러, 또는 장 중 사건이 생긴 요청의 `ctx.waitUntil`. 사건 처리 요청 자체는 AI 응답을 기다리지 않는다. 장 중 사건은 가격 반영 시점에 AI 기사가 준비되지 않았으면 템플릿 기사를 즉시 공개하고, 그 기사는 바꾸지 않는다.

### 8-4. 큰손 소식

- 한 번에 20,000G 이상 또는 100주 이상 체결되면(결정) `익명의 큰손, 예굼 300주 매수` 같은 기사를 낸다. 누가 샀는지는 절대 밝히지 않는다. 가격 영향은 없다(조작 방지). 같은 사람·같은 종목은 1시간에 1번만.

### 8-5. 예산 상한

- 요금 상수(`shared/balance.ts`의 `AI_RULES`): 입력 $4, 출력 $20, 캐시 쓰기 $5, 캐시 읽기 $0.20 (모두 100만 토큰당, Claude Opus 5.5 기준). **작업 시점에 Anthropic 공식 가격표로 다시 확인**하고 주석에 확인 날짜를 적는다.
- 호출마다 응답 `usage`로 비용을 계산해 `ai_usage`에 더한다(생각 토큰은 출력에 포함되어 청구된다).
- **하루 합계가 0.80달러에 닿으면** 그날은 더 호출하지 않고 템플릿만 쓴다. 사용자가 정한 하루 1달러를 넘지 않게 하는 안전장치다. 08:50 묶음 호출 전에 예상 비용(입력 토큰 수 × 단가 + `max_tokens` 상한)을 계산해 남은 예산을 넘으면 사건 수를 줄인다.
- 예상 사용량: 하루 0.3~0.6달러, 장 서는 날 기준 한 달 6~12달러. 실제 값은 운영 탭에서 보인다.

### 8-6. 운영 탭 (공개 전 미리보기 없음)

- 운영자는 공개 전 뉴스·예정 사건을 **볼 수 없다**(§1-2).
- 할 수 있는 것: ① **이미 공개된** 뉴스 숨기기(부적절한 문장 대비, 가격 영향은 되돌리지 않음), ② AI 켜기/끄기 스위치(끄면 템플릿만), ③ 오늘·이번 달 AI 호출 수와 비용, ④ 임시 휴장일 관리(§3).

## 9. 화면

지금의 `src/screens/Stock.tsx` 구조를 살려 실제 데이터로 바꾼다.

1. **시장 목록(`/stock`)**: 장 상태와 시각(`장 열림 · 18시 00분 마감`), 내 주식 평가금액·평가손익 합계, 10종목 행(배지 아이콘, 종목명, 현재가, 전일 대비 %, 배지: 상한가·하한가·관리종목·상장폐지·거래 정지, `N주 보유`), 아래에 오늘 뉴스 최신 5개와 `뉴스 전체 보기`.
2. **종목 상세(`/stock/:ticker`)**: 차트(1일 10분봉 / 1주 / 1개월 일봉 토글, 기존 `Chart`의 상·하한가 선 유지), 회사 소개(§2), 이 종목 뉴스, 내 보유(수량·평균 단가·평가손익), 매수·매도(수량 입력 + 빠른 버튼 1·10·최대, 수수료와 최종 금액 표시, 기존 확인 시트).
3. **뉴스(`/stock/news`)**: 오늘(및 지난 거래일) 뉴스를 시간순. 기사 카드에 시각(§1-3 형식), 종목 배지, 그 순간의 등락 반영값(`+6.2%`), `[찌라시]` 라벨.
4. **장 마감 화면**: 오늘의 시황 요약 + 나에게만 보이는 한 줄 코멘트 + 내 오늘 손익.
5. **홈 `주식 시장` 타일**: `장 열림 · 내 손익 +1,240G` / `장 마감` / `휴장(크리스마스)`.
6. **새 뉴스 알림**: 주식 화면을 보고 있을 때 새 기사가 공개되면 토스트 `속보 · 예굼, 모기 사냥 성공`.
7. **폴링(무료 플랜):** 주식 화면이 보일 때만, **다음 10분 틱 직후**(예: 정각+10분+5초)에 한 번씩 읽는다. 30초마다 읽지 않는다. 장 중 사건으로 가격이 바뀌는 경우를 위해 `stock_state.version`으로 "변경 없음" 짧은 응답을 지원한다(캐치마인드 §3-1-4와 같은 방식).
8. 내 정보 골드 내역에 매수·매도가 보이고, 아이콘 규칙(`iconFor`)에 주식을 추가한다.
9. 랭킹 형태의 목록이 생기면 이름에 "님"을 붙이지 않는다(§1-1-1).
10. 미리보기(`#/preview/stock`)는 서버 없이 같은 엔진(난수만 고정 시드)과 템플릿 뉴스로 동작한다.

## 10. 테스트

- 엔진: 같은 시드 → 같은 가격, 빠진 틱 보충 결과 = 정상 실행 결과, ±15% 제한, 휴장일·주말·예굼 겨울 정지, 1,000회 모의실험 분포(상장폐지 빈도).
- 매매: 수수료·반올림, 500주 한도, 잔액·보유 부족, 장 마감, 버전 충돌, 같은 `requestId` 재요청, 동시 요청 중복 차감 없음, 운영자 403, 원장 합계 = 잔액 캐시.
- 상장폐지: 관리종목 → 회복 / 상장폐지 → 보유 0·기록 / 10거래일 뒤 재상장.
