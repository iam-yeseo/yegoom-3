# 예굼방 아케이드 3 — 캐릭터 뽑기 이식 계획 (Codex 작업 지시서, Phase 6)

기존 `iam-yeseo/yegoom`의 **캐릭터 뽑기방(물리 인형뽑기)**을 yegoom-3로 옮긴다. 핵심 동작과 손맛은 **그대로 유지**하고, yegoom-3 구조와 디자인, 경제(골드·점수), 무료 플랜 제약에 맞게 다듬는다. `docs/plan-v2.md`의 **0장 공통 규칙**(단일 규칙 소스, ledger 원칙, 추가형 마이그레이션, 작업 방식, 보고 형식)을 그대로 따른다. 이 문서에 없는 결정이 필요하면 추측하지 말고 멈춘 뒤 보고한다.

시작할 때 이 문서를 `docs/plan-claw.md`로 레포에 커밋한다. 최신 `main`에서 `codex/v3-claw` 브랜치를 만든다. Draft PR을 열고 멈춘다.

### 1-1. 반드시 유지할 동작
- **결과는 서버가 물리 시뮬레이션으로 정한다.** 브라우저는 같은 입력(x, 멈춘 높이, 집게 힘)으로 같은 시뮬레이션을 돌려 **재생**만 한다. 그래서 화면에서 본 것이 곧 결과다. 재생 결과가 서버 결과와 다르면 결과만 보여 준다(원본의 `consistent` 검사 유지).
- **사용자별 기계**: 인형 30개, 11종 무작위, 종류마다 크기·무게가 다르다. 떨어진 인형은 그 자리에 남는다. 30개를 모두 뽑으면 새 기계(다음 세대)가 준비된다.
- **조작**: 코인 넣기 → 10초 안에 ◀ ▶로 집게 이동(버튼을 누르고 있는 동안 이동, 가속·감속·흔들림) → 내리기 → 내려가는 중 한 번 더 누르면 그 높이에서 멈춰 집기. 시간이 다 되면 그 자리에서 내려간다. PC는 ←/→, Space를 지원한다.
- **확률기(집게 힘)**: 플레이어마다 코인 수를 세서 `payoutEvery`번째 판은 강집게(100%)다. 나머지는 약집게(들어 올리는 힘 `weakPickup`%, 옮기는 힘 `weakCarry`%, 매 판 ±10% 흔들림)다. 강집게가 나오거나 인형을 뽑으면 다시 센다. 기본값은 원본과 같은 10 / 45 / 30이다.
- **연출**: 착지 예상 지점 조명, 집게 흔들림, 경품이 배출구로 굴러갈 때 슬로모션, 배출구 깜빡임, 단계별 상태 문구("잡았다! 조금만 더 힘내…", "아깝다! 배출구가 코앞이었는데…" 등), 효과음, 진동, 남은 5초 틱 소리
- **멱등·복구**: `requestId`와 기계 `version`으로 한 판은 한 번만 처리한다. 응답이 끊겨도 같은 요청으로 결과를 복구하고, 코인을 두 번 쓰지 않는다. 진행 중 연타 방지(`next_play_at`)도 유지한다.

## 2. yegoom-3에 맞게 바꿀 것 (확정된 PM 결정)

### 2-1. 인형
- 원본 11종을 그대로 쓴다. 바이트를 그대로 복사하지 말고 **웹용으로 최적화**한다. 원본 PNG는 장당 180~430KB, 총 3.3MB다.
  - 투명 배경 유지, 긴 변 320px WebP(alpha 무손실, RGB quality 85 내외), 장당 40KB 이하 목표
  - 경로 `public/claw/dolls/doll-1.webp` ~ `doll-11.webp`, 번호는 원본 `type`(1~11)과 같게 한다
  - 변환 스크립트를 `scripts/prepare-claw-dolls.py`로 남긴다
- `docs/design.md`(또는 새 `docs/asset-provenance.md`)에 출처를 기록한다. 내용은 "사용자가 제공한 이미지, 원본 yegoom `public/assets/gatcha-*.png`에서 최적화, 지인용 비공개 서비스 전용"이다.
- PWA: 인형 이미지 11장은 미리 캐시에 넣는다(합계 약 0.5MB 이내).

### 2-2. 코인과 비용
- **무료 코인**: 한국 시간 00·03·06·09·12·15·18·21시마다 **5개로 채운다**(원본 10개에서 변경). 남은 무료 코인과 접속하지 않은 시간의 코인은 이월되지 않는다. 원본처럼 **요청이 올 때 지연 지급**한다(Cron 사용 금지).
- **구매 코인**: 골드로 산다. **1개 100G**, 한 번에 1개 또는 5개(500G)를 살 수 있다. 구매 코인은 사라지지 않는다. **무료 코인부터 사용**한다.
- 골드 차감은 ledger에 `requestId` 기반 reference로 남기고, 잔액 검사와 차감을 한 번의 조건부 batch로 처리한다(0-3 원칙).
- 하루 플레이 횟수 제한은 두지 않는다. 코인이 곧 제한이다.

### 2-3. 보상
| 결과 | 보상 |
| --- | --- |
| 인형 1개 배출 | **1점 + 10G** (한 판에 여러 개가 굴러 들어가면 개수만큼) |
| 기계의 30개를 모두 뽑음(클리어) | 추가 **5점 + 300G**, 새 기계 |

- 점수 행의 `week_start`는 플레이 시각(KST) 기준이다. reference는 `claw:doll:<playId>`, `claw:clear:<playId>` 형식으로 멱등하게 둔다.
- 랭킹·홈·내 정보 내역에 다른 게임과 같은 방식으로 반영한다.

### 2-4. 확률기 설정은 서버에만
- `payoutEvery`, `weakPickup`, `weakCarry`는 **`shared/`에 두지 않는다.** 클라이언트 번들에 들어가면 플레이어가 강집게 시점을 계산할 수 있다.
- DB 단일 행 테이블 `claw_config`(기본값 10 / 45 / 30, 범위 검사 포함)에 둔다. 운영자 웹 화면은 아직 없으므로 지금은 `wrangler d1 execute`로만 바꾼다. 바꾸는 방법을 README 운영 절에 적는다.
- 플레이 응답에는 **그 판에 실제로 쓴 집게 힘**만 담는다. 재생에 필요하기 때문이다. 다음 강집게까지 남은 횟수는 절대 내려보내지 않는다.

### 2-5. 화면과 디자인
- 지금의 미리보기 전용 뽑기 화면(`src/components/PreviewGames.tsx`의 `Claw`, `ClawSuccess`, `prizes`, `TARGET`, 집게 위치 0.38 판정)과 `BALANCE.claw`를 **이 구현으로 교체**한다.
- 기계 외형은 원본 구성을 유지하되 **yegoom-3 디자인 토큰**으로 다시 그린다. 원본의 굵은 검정 윤곽선 스타일은 쓰지 않는다.
  - 구성: 간판과 깜빡이는 전구, 유리창(캔버스), 콘솔(◀ ▶, TIME, 코인 넣기/내리기/멈추기 버튼), 코인 투입구
  - 기존 `.pg-machine` 코랄 프레임과 `--claw-machine-width: 400px` 폭 제한을 유지한다
  - 캔버스 안쪽(배경, 바닥, 배출구, 칸막이, 레일, 집게)도 yegoom-3 팔레트(민트·코랄·라벤더·크림, `#3A3340` 계열 선)로 칠한다
- **캔버스 선명도**: 원본은 600×420 고정 해상도를 CSS로 늘려서 고해상도 화면에서 흐리다. 논리 좌표는 600×420을 유지하고, 캔버스 버퍼만 `표시 크기 × devicePixelRatio`(최대 3)로 맞춰 선명하게 그린다.
- **결과 창**: 원본의 장면 그림(`assets/gatcha/*.webp`)은 원본 그림체라 가져오지 않는다.
  - 뽑았을 때: 뽑은 인형 사진(최대 3개), 점수·골드, 컨페티. CLEAR는 추가 보너스를 표시한다.
  - 못 뽑았을 때: 원본의 상황별 제목과 설명 문구(미끄러짐·옮기다 떨어짐·배출구 코앞·너무 일찍 멈춤·집게가 못 감쌈)를 유지하고, 그림은 **내 캐릭터 정지 이미지**를 쓴다.
  - 결과 창은 기존 앱 시트·다이얼로그 스타일을 따른다.
- **지갑 영역**: 무료 코인 수, 구매 코인 수, 다음 충전까지 남은 시간(초 단위), 코인 사기 버튼(1개 100G, 5개 500G)
- **안내**: "게임 규칙 & 보상" 아코디언. 조작법, 코인 충전 규칙, 보상, "집게 힘은 판마다 다르다"는 문구를 넣는다. 확률기 수치는 쓰지 않는다.
- **홈 배너와 게임 탭**: "캐릭터 뽑기" 카드에 지금의 "오늘 남은 횟수 3/5" 대신 **보유 코인 수와 다음 충전 시각**을 보여 준다.
- **소리**: 원본처럼 효과음을 켠다. 기본값은 **켜짐**이고, 끄기/켜기 버튼으로 바꾸며 선택은 기기에 기억한다(localStorage, 실패 시 무시). 첫 소리는 사용자가 누른 뒤에만 시작한다(자동재생 제한).
- **진동**: 원본 `buzz` 패턴을 유지한다(지원 기기만). 소리를 끄면 진동도 끈다.
- **동작 줄이기**: 원본처럼 재생을 2배속으로 하고, 집게 흔들림·전구 깜빡임·컨페티를 끈다. 결과 창은 그대로 보여 준다.
- 기계 캔버스와 콘솔 버튼에는 `data-notouchfx`를 붙여 전역 터치 이펙트가 조작을 가리지 않게 한다.
- **미리보기 모드**(`#/preview`): 서버 없이 브라우저에서 같은 물리 엔진으로 플레이된다. 결과는 저장하지 않고 코인은 기기 안에서만 줄어든다.

### 2-6. 운영자
- 운영자는 기계를 볼 수 있지만(원본처럼 데모 기계) 코인 구매와 플레이는 할 수 없다(403).

## 3. 서버 구조

### 3-1. 마이그레이션 `0006_claw.sql` (추가형)
- `claw_config` (id=1 단일 행): `payout_every`, `weak_pickup`, `weak_carry`, `updated_at`. 원본 범위 검사(1~50, 5~100, 5~100)를 넣고 기본 행을 INSERT한다.
- `claw_accounts`: `user_id` PK, `free_coins`, `purchased_coins`(둘 다 ≥0), `last_grant_slot`, `board_json`, `generation`, `version`, `next_play_at`, `power_counter`
- `claw_plays`: 원본 `gatcha_plays`를 참고한다. `UNIQUE(user_id, request_id)`, `UNIQUE(user_id, version)`, `result_json`, 획득 인형 수, 클리어 여부, `created_at`
- 구매 기록은 기존 `shop_purchases`를 재사용하지 않는다(종류 CHECK 제약 때문). `claw_coin_purchases`(requestId UNIQUE, 수량, 비용)를 둔다.

### 3-2. API
| 메서드·경로 | 내용 |
| --- | --- |
| `GET /api/claw` | 지연 코인 지급 → 내 기계 상태(board, version, generation, 코인, 다음 충전 시각, nextPlayAt). **시뮬레이션을 돌리지 않는다** |
| `POST /api/claw/coins` | `{ requestId, quantity: 1 \| 5 }` 골드로 코인 구매 |
| `POST /api/claw/play` | `{ requestId, version, x, stop }` → 서버 시뮬레이션 → 기록·코인 차감·보상·새 판을 한 batch로 처리 → `result`와 새 상태 |

- 입력 검증은 원본 `validatePlay` 범위를 따른다.
- bootstrap에는 홈 배너용 요약(코인 수, 다음 충전 시각)만 넣는다. 기계 판 전체는 넣지 않는다.

### 3-3. 무료 플랜 제약 (필수)
- **CPU**: 시뮬레이션 1회는 Node 기준 중앙값 약 4ms, 상위 1% 약 23ms다(원본으로 측정). 원본 앱은 같은 무료 계정에서 CPU 초과 오류 없이 동작했다. 다음을 지킨다.
  - 시뮬레이션은 `POST /api/claw/play`에서만 한 번 돌린다. 재시도(같은 requestId)는 저장된 결과를 돌려준다.
  - 시뮬레이션 최대 프레임 수 상한을 원본 그대로 유지하거나 명시적으로 둔다(무한 루프 방지).
  - 통합 테스트에 무작위 입력 300회 시뮬레이션 시간 측정을 넣고, 상위 1%가 40ms를 넘으면 실패시킨다. 측정값은 보고에 적는다.
- **D1 읽기**: `GET /api/claw`와 bootstrap 요약은 한 사용자의 행 몇 개만 읽어야 한다. 전체 기록을 SUM하는 쿼리를 매번 실행하지 않는다. 보고에 요청별 `rows_read`(D1 meta)를 적는다.
- **폴링 금지**: 뽑기 화면은 주기적으로 새로 고치지 않는다. 화면 진입, 플레이 후, 화면 복귀(visibilitychange), 다음 충전 시각 도달 때만 조회한다.

## 4. 물리 엔진 이식 규칙 (가장 중요)
- `gatcha-physics.js`를 `shared/claw-physics.ts`로 옮길 때 **계산식, 연산 순서, 상수를 바꾸지 않는다.** 원본은 서버와 브라우저의 결과를 비트 단위로 같게 하려고 `+ - * /`와 `Math.sqrt`만 쓴다. 이 원칙을 지킨다. 타입만 붙인다.
- **골든 테스트**: 원본 JS 파일을 테스트 fixture로 복사해 두고(`tests/fixtures/gatcha-physics.original.js`), 다양한 시드·위치·멈춤 높이·집게 힘 조합 200가지 이상에서 원본과 이식본의 `simulateAttempt` 결과(JSON 전체: 판, 경품, 이유, 프레임 수)가 **완전히 같은지** 검사한다. `createBoard(세대, 시드)`도 같은 방식으로 검사한다.
- 서버 시뮬레이션과 브라우저 재생이 같은 결과를 내는지 e2e로 한 번 확인한다(원본의 consistent 검사가 통과하는지).
