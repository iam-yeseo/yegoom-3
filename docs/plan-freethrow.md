# 예굼방 아케이드 3 — 자유투 대결 계획

혼자 하기 게임 **자유투 대결**을 세 단계로 만든다. 공을 아래로 당겼다가 위로 쓸어 올리며 놓으면 슛이 나가는 세로 화면 2.5D 게임이다. 가장 중요한 원칙은 **같은 동작이면 언제나 같은 결과**다. 실패 이유를 보고 다음 슛을 조절할 수 있어야 손에 익는 재미가 생긴다.

## 1. 확정된 결정 (2026-11-07)

| 항목 | 결정 |
| --- | --- |
| 보상 | 공식 도전에서 1골마다 **1점 + 5G**. 연습 모드는 보상 없음 |
| 공식 도전 | 캐릭터 뽑기 코인처럼 **3시간마다 1세트**(KST 00·03·06·09·12·15·18·21시), 1세트에 **10구**. 남은 세트는 이월하지 않음 |
| 친구 대결 | 따로 매칭하지 않음. 각자 같은 조건에서 던진 공식 세트 기록을 비교 |
| 주식 연동 | 보류 (개인전이라 어떤 종목과 묶을지 나중에 정함) |
| 도전과제 | 운영 시트 `도전과제` 탭에 추가됨 (아래 §5) |

규칙 상수는 `shared/balance.ts`의 `FREETHROW_RULES`에 있다. `officialOpen`은 2단계가 끝날 때 `true`로 바꾼다.

### 2-1. 물리
- 실제 코트 치수: 공 반지름 0.12m, 링 반지름 0.2286m·높이 3.05m, 놓는 지점에서 링 중심까지 4.19m, 링 뒤 0.38m에 백보드.
- 3D로 계산하고 그릴 때만 화면에 투영한다. 화면 좌표로 충돌을 계산하면 원근 때문에 링 판정이 어긋난다.
- 1/240초 고정 간격, 최대 5초. 사칙연산과 `Math.sqrt`만 쓴다(`shared/claw-physics.ts`와 같은 원칙). 발사 각도(약 52°)는 cos·sin 상수로 넣었다.
- 입력은 정수 두 개(`power`, `aim`)라서 저장하고 서버에서 똑같이 다시 계산할 수 있다.
- 골 판정: 공 중심이 링 높이를 위에서 아래로 지날 때 링 안쪽이면 성공. 처음 닿은 것이 없으면 클린 슛, 백보드면 뱅크 슛, 림이면 림 맞고 골.
- 실패는 처음 닿은 곳으로 설명한다: 앞 림(약함), 뒷 림(셈), 백보드(너무 셈, 링 폭 밖이면 방향), 아무 데도 안 닿음(짧음·길음·왼쪽·오른쪽).
- 결과표(방향 0): 세기 0~33 짧음, 34~45 앞 림, **50~60 골 구간**, 61~70 뒷 림 위주, 71~79 백보드 맞고 들어가는 구간, 80 이상 백보드 맞고 나감. `tests/freethrow-physics.test.ts`가 이 모양과 전체 결과 지문을 지킨다.

### 2-2. 손동작
- 공 근처(반지름 1.8배)를 눌러야 잡힌다. 잡은 공은 손가락을 따라 아래로 최대 0.15만큼 내려온다.
- **손을 떼기 직전 110ms** 동안의 움직임만 슛을 정한다. 아래로 당긴 준비 동작은 결과에 섞이지 않는다.
- 모든 좌표를 경기장 높이로 나눈 단위로 계산한다. 390px 폰과 560px 화면에서 같은 손동작이 같은 슛이 된다.
- 세기 = 위로 올리는 속도 ÷ 4.4(경기장 높이/초). 속도에 비례하므로 손 빠르기 ±10%가 세기 약 ±5다.
- 방향 = 옆으로 움직인 비율 ÷ 0.8. 곧게 올리면 0이다.
- 손을 떼는 이벤트가 마지막 위치를 늦게 한 번 더 보내는 것은 멈춤으로 보지 않는다. 60ms 넘게 멈췄다 떼면 느린 슛으로 본다.
- 위로 0.07 미만으로 올렸거나 너무 느리면 슛하지 않고 공을 돌려준다. `pointercancel`도 취소다.
- 60Hz·120Hz 화면 차이는 창 경계 보간으로 맞춘다. `getCoalescedEvents()`가 있으면 쓴다.

### 2-3. 화면
- 정면 고정 시점. 백보드·골대는 위쪽, 공은 중하단에 두고 그 아래에 당길 여백을 둔다.
- 림은 살짝 위에서 본 것처럼 기울여 그리고(그리기 전용), 공 위치에 따라 백보드·림 뒤쪽·그물·림 앞쪽과의 앞뒤 순서를 바꾼다.
- 바닥은 장식용 코트이고, 그림자는 공이 얼마나 멀리·옆으로 갔는지를 보여 준다. 실제 바닥은 화면 아래에 있으므로 떨어지는 공은 손 높이 아래에서 사라진다.
- 링에 맞으면 림이 떨리고, 골이 들어가면 그물이 늘어났다 흔들린다. 2연속부터 `N연속!` 배지.
- 방금 슛의 세기(막대)와 방향(`가운데`·`왼쪽 12`)을 보여 준다. 정답 구간은 표시하지 않는다.
- 정지 상태에서는 그리기 루프를 돌리지 않는다. 캔버스 버퍼는 표시 크기 × DPR(최대 2).
- 동작 줄이기: 림 떨림·그물 흔들림·안내 손가락 애니메이션을 끈다. 슛 재생 속도는 그대로다.
- 소리는 기본 켜짐, 기기에 기억(`yegoom3:freethrow:muted`). 첫 소리는 공을 잡은 뒤에만.
- 홈과 게임 탭의 **혼자 하기**에 타일을 추가했다. 타일이 홀수일 때 마지막 타일은 한 줄 전체를 쓴다.

### 2-4. 조정할 곳
실제 손으로 던져 보고 맞춘다. 숫자는 모두 한곳에 모여 있다.
- 손 빠르기 → 세기: `GESTURE.fullPowerSpeed`(지금 4.4). 대부분 짧으면 낮추고, 대부분 길면 높인다.
- 방향 민감도: `GESTURE.fullAimSlope`(0.8), 엔진 `AIM_RATIO`(0.105).
- 골 구간 폭·튕김: `SPEED`, 림·백보드 반발 계수. **엔진 값을 바꾸면 결과 지문 테스트를 일부러 갱신해야 한다.** 2단계 이후에는 이미 기록된 세트와 결과가 달라지므로 엔진 버전을 함께 올린다.

## 3. 2단계 — 공식 10구 (다음 작업)

### 3-1. 세트와 부정 방지
- 3시간 칸(`floor(now / 3h)`, 뽑기의 `coinSlot`과 같은 계산)마다 세트 하나. 지연 지급이며 Cron을 쓰지 않는다.
- **세트를 시작할 때 서버에 판을 만든다.** 그 순간 이번 칸의 기회를 쓴다. 다 던진 뒤 한꺼번에 제출하면 망한 판을 새로고침해서 다시 할 수 있기 때문이다.
- 슛마다 바로 서버에 보낸다(`세트 번호 + 몇 구째`가 유일). 화면은 서버를 기다리지 않고 즉시 재생하고, 서버는 같은 엔진으로 다시 계산해 기록한다. 숨길 값이 없으므로 뽑기와 달리 결과를 먼저 보여 준다.
- 중간에 나가면 남은 공은 실패. 칸이 바뀌면 끝나지 않은 세트를 닫는다(다음 요청이나 조회 때).
- 같은 요청 재시도는 저장된 결과를 돌려준다. 세기·방향이 다른 재시도는 409.
- 운영자는 연습만 한다(뽑기처럼 403).

### 3-2. 마이그레이션 `0026_freethrow.sql` (추가형)
- `freethrow_sets`: `id`, `user_id`, `slot`(3시간 칸), `request_id`, `engine`, `made`, `shots`, `closed_at`, `created_at`, `UNIQUE(user_id, slot)`, `UNIQUE(user_id, request_id)`
- `freethrow_shots`: `set_id`, `shot_index`(0~9), `power`, `aim`, `made`, `kind`, `created_at`, `PRIMARY KEY(set_id, shot_index)`

### 3-3. API
| 메서드·경로 | 내용 |
| --- | --- |
| `GET /api/freethrow` | 이번 칸의 내 세트(없으면 시작 가능), 다음 칸 시각, 이번 칸·오늘 친구들 기록 |
| `POST /api/freethrow/sets` | `{ requestId }` 이번 칸 세트 시작 |
| `POST /api/freethrow/shots` | `{ setId, index, power, aim }` 서버 재계산 → 기록 → 골이면 원장 |

- 원장: `freethrow:goal:<setId>:<index>:score|gold`, 점수 행의 `week_start`는 슛 시각 기준.
- bootstrap에는 홈 타일 요약(이번 칸 남은 세트 여부·다음 칸 시각)만 넣는다. 주기 조회는 하지 않는다.
- CPU: 슛 한 번 계산은 Node 기준 0.01ms 수준이다(테스트가 1000회 1초 미만, 최장 20ms 미만을 지킨다).

### 3-4. 화면
- 연습 / 공식 도전 전환. 공식 도전은 남은 공 10개 표시, 세트 결과 창(몇 골, 받은 점수·골드).
- **오늘의 기록판**: 이번 칸과 오늘 친구들의 최고 세트. 같은 칸끼리 비교한다.
- 홈 타일: `이번 세트 도전 가능` / `다음 세트 15시`.

## 4. 3단계 — 랭킹·도전과제·더 하기
- 랭킹: `shared/ranking-periods.ts`의 `ScoreGame`에 `freethrow`(라벨 `자유투`) 추가, `freethrow:` 기록 분류.
- 도전과제(§5) 판정을 `worker/achievements.ts`에 추가.
- 연속 성공 모드, 골대 거리 변경, 공 스킨, 주식 연동은 그다음에 정한다.

## 5. 도전과제 (운영 시트 `도전과제` 탭, 유형 `게임하기`)

| 달성조건 | 제목 | 보상 | 반복 |
| --- | --- | --- | --- |
| 자유투 대결 첫 참여 | 준비하시고 쏘세요! | 50 | |
| 자유투 대결 3골 성공 | 이정도면 충분한가? | 50 | 1일 1회 |
| 자유투 대결 5골 성공 | 절반의 성공, 절반의 실패 | 100 | 1일 1회 |
| 자유투 대결 10골 성공 | 조작하지 마세요 | 150 | 1일 1회 |
| 자유투 대결 0골 성공 | 내 손가락을 탓하지 말아주세요 | 300 | |

- "N골 성공"은 **공식 세트 하나에서 N골 이상**으로 판정하자고 제안한다(3골 과제는 5골·10골 세트에서도 달성). 0골은 공식 세트 10구를 모두 던지고 0골일 때. 연습 모드는 판정하지 않는다.
- 판정은 2단계 기록이 생겨야 가능하므로 3단계에서 넣는다.
